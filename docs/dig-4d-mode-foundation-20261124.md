# DIG 4차원 무한 채굴 모드 구현 착수

기준 브랜치: `main` (기존 4개 광산과 공개 Pages 유지)  
작업 브랜치: `feat/dig-4d-mode-foundation-20261124`

## 구현 판단

현재 플레이 가능한 결과물은 제한 크기 복셀 광산을 중심으로 동작한다. 무한 청크, 4차원 통로, 열차·화물, 거래 드론, 이메일 복원 문자열은 런타임에 연결되어 있지 않다. 기존 런타임을 통째로 교체하지 않고 **별도 모드**로 추가한다.

재사용 후보: Three.js 렌더러·모바일 입력·오디오·자동 채굴 상태 전이·기계 대사·추진 계산.  
새로 설계할 핵심: 세션 한정 청크 스트리밍, 구체형 기계, 열차와 화물, 포털 중력, 4차원 물품 방출, 거래·백업.

## 세계와 기억 설정

- 플레이어는 사람이 아닌 구체형 채굴 기계다.
- 청크 위치와 4차원 통로 연결 관계는 플레이어가 알 수 없다. 고정 월드 시드나 영구 포털 지도를 제공하지 않는다.
- 현재 세션의 월드 청크는 런타임에서만 유지한다. 재접속하면 주변 환경·현재 위치·통로 연결 기록을 복구하지 않고 새 환경에서 시작한다.
- 대형 통로로 이동할 때도 이전 청크 환경과 위치 기록을 버리고, 새 출구가 있는 환경을 생성한다.
- 열차에 실린 장비·인벤토리·연구·도감 등 진행 데이터는 환경과 분리해 유지한다. 열차에 싣지 않은 물품은 환경 초기화 때 사라진다.
- 재접속 시에만 짧은 독백을 표시해 기억이 온전하지 않다는 점을 은근히 암시한다. 새 게임 시작에는 표시하지 않는다. 예: “열차는 그대로인데… 여긴 처음 보는 곳 같아.”

## 구현 단계

1. **격리 기반:** 별도 모듈과 열차 저장 키, 청크 좌표, 통로 중력 방향.
2. **세션 월드:** 세션 중 청크 스트리밍·광물 노출·채굴·청크 초기화. 재접속 시 월드 상태는 폐기.
3. **플레이어와 열차:** 구체형 채굴 기계, 선두 통합차, 후미 화물차, 길이·소실 위험.
4. **4차원 통로:** 출구/입구, 채굴보다 훨씬 느린 물품 방출, 흡입 이동, 새 출구 청크 생성.
5. **성장·거래:** 레이저 세라믹, 상위 장비, 거래 드론, 고정가·경매 흐름.
6. **복원:** 공유 가능한 암호화 문자열, 인증 이메일 발송, 복원 전 현재 상태 백업 메일.

이메일 발송은 정적 GitHub Pages만으로 안전하게 처리할 수 없으므로 서버 측 발송 경로를 별도로 설계한다.

## 현재 기반과 남은 작업

- 완료: 별도 모듈 경로·열차 저장 키, 16m/0.5m 청크 주소 계산, 음수 좌표 floor 처리.
- 완료: 통로 입구/출구 중력 방향 계산, 청크 거리 기반 활성·유지·초기화 가능 상태 분류.
- 완료: 재접속 전용 기억 암시 대사 선택기. 새 게임 시작에서는 대사를 반환하지 않는다.
- 다음: 세션 청크 생성/폐기, 구체형 기계 이동과 중력 물리, 열차/화물/통로 런타임 통합.
- 검증 상태: TypeScript 빌드·자동 테스트·브라우저 실행·Pages 배포는 아직 하지 않았다. `main`과 기존 게임 저장은 변경하지 않았다.
