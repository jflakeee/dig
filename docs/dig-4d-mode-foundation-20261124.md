# DIG 4차원 무한 채굴 모드 구현 착수

기준 브랜치: `main` (기존 4개 광산과 공개 Pages 유지)  
작업 브랜치: `feat/dig-4d-mode-foundation-20261124`

## 구현 판단

현재 플레이 가능한 결과물은 제한 크기 복셀 광산을 중심으로 동작한다. 무한 청크, 4차원 통로, 열차·화물, 거래 드론, 이메일 복원 문자열은 런타임에 연결되어 있지 않다. 따라서 기존 런타임을 통째로 교체하지 않고 **별도 모드**를 추가한다.

재사용 후보: Three.js 렌더러·모바일 입력·오디오·자동 채굴 상태 전이·기계 대사·추진 계산.  
새로 설계할 핵심: X/Y/Z 청크 저장·스트리밍·초기화, 구체형 기계 이동/시각, 열차와 화물, 포털 중력, 4차원 물품 방출, 거래·백업.

## 단계

1. **격리 기반:** 별도 모듈 경로와 세이브 키, 청크 좌표 산출, 통로 중력 방향 계산.
2. **월드:** 16m 청크 스트리밍, 최초 노출 시 광물 결정, 청크 초기화/복원 정책.
3. **플레이어와 열차:** 구체형 채굴 기계, 선두 통합차, 후미 화물차, 길이·소실 위험.
4. **4차원 통로:** 출구/입구, 느린 방출, 흡입 이동, 새 출구 청크 생성.
5. **성장·거래:** 레이저 세라믹, 상위 장비, 거래 드론, 고정가·경매 흐름.
6. **복원:** 공유 가능한 압축 암호화 문자열, 인증 이메일 발송, 복원 전 현재 상태 백업 메일.

각 단계는 기존 모드의 세이브 키와 화면 진입점에 연결하기 전에 독립적으로 검토한다. 이메일 발송은 정적 GitHub Pages만으로 안전하게 처리할 수 없으므로 서버 측 발송 경로를 별도로 설계한다.

## 이번 착수 범위

- 기존 게임 파일과 저장 형식은 수정하지 않는다.
- 새로운 `src/digMode/` 경로를 만든다.
- 청크 좌표 계산은 음수 좌표에서 floor 규칙을 사용한다.
- 통로 중력 함수는 입구/출구 방향만 계산한다. 중력장의 범위·감쇠·복수 통로 합성은 확정 전이므로 구현하지 않는다.
- 신규 모드는 기존 세이브와 독립된 키를 예약한다.

## 진행 상태

- 완료: 별도 모듈 경로와 세이브 키, 16m/0.5m 청크 주소 계산 및 음수 좌표 floor 처리.
- 완료: 청크별 버전 레코드(초기화 epoch, 제거 복셀, 노출 자원 기록), 손상 데이터 거부, 청크 초기화 시 기록 비우고 epoch 증가.
- 완료: 최초 노출 광물 결정 함수. 월드 시드·청크 좌표·복셀 ID·epoch·표 버전으로 결정하며 65/18/10/5/2 기본 비율을 사용한다. 4차원 출구 방출은 별도 흐름으로 유지한다.
- 미완료: 청크 렌더 스트리밍, 광석 노출 이벤트 연결, 플레이어 이동 및 통로 중력 물리, 열차/거래/복원 런타임 통합.
- 검증 상태: TypeScript 빌드·자동 테스트·브라우저 실행·Pages 배포는 아직 하지 않았다. `main`과 기존 게임 저장은 변경하지 않았다.
