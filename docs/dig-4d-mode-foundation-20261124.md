# DIG 4차원 무한 채굴 모드 구현 착수

기준 브랜치: `main` (기존 4개 광산과 공개 Pages 유지)  
작업 브랜치: `feat/dig-4d-mode-foundation-20261124`

## 구현 판단

현재 플레이 가능한 결과물은 제한 크기 복셀 광산을 중심으로 동작한다. 무한 청크, 4차원 통로, 열차·화물, 거래 드론, 이메일 복원 문자열은 런타임에 연결되어 있지 않다. 기존 런타임을 통째로 교체하지 않고 **별도 모드**로 추가한다.

재사용 후보: Three.js 렌더러·모바일 입력·오디오·자동 채굴 상태 전이·기계 대사·추진 계산.  
새로 설계할 핵심: 세션 한정 청크 스트리밍, 구체형 기계, 열차와 화물, 포털 중력, 4차원 물품 방출, 거래·백업.

## 세계와 기억 설정

- 플레이어는 사람이 아닌 구체형 채굴 기계다.
- 청크 위치와 4차원 통로 연결 관계는 플레이어가 알 수 없다. 고정 월드 시드나 영구 포털 지도를 제공하지 않는다.
- 현재 세션의 월드 청크는 런타임에서만 유지한다. 재접속하면 주변 환경·현재 위치·통로 연결 기록을 복구하지 않고 새 환경에서 시작한다.
- 대형 통로로 이동할 때도 이전 청크 환경과 위치 기록을 버리고, 새 출구가 있는 환경을 생성한다.
- 열차에 실린 장비·인벤토리·연구·도감 등 진행 데이터는 환경과 분리해 유지한다. 열차에 싣지 않은 물품은 환경 초기화 때 사라진다.
- 재접속 시에만 짧은 독백을 표시해 기억이 온전하지 않다는 점을 은근히 암시한다. 새 게임 시작에는 표시하지 않는다. 예: “열차는 그대로인데… 여긴 처음 보는 곳 같아.”

## 성능과 청크 초기화 정책

한 청크만 메모리에 있어도 게임 설정상 문제가 없으므로, 기기 성능에 따라 세계 초기화 거리를 달리할 필요는 낮다. **256m 초기화 경계는 모든 기기에서 동일하게 유지**해 먼 환경이 사라지는 규칙을 일관되게 한다. 낮은 성능 기기는 시각 품질, 메시 분할/해제, 렌더 거리로 최적화하고 단순 FPS 저하만으로 월드 기록을 더 일찍 삭제하지 않는다. 심각한 메모리 부족 대응은 별도 검토 사항이다.

먼지 안개는 224m부터 짙어져 256m에서 완전히 가리도록 설정한다. 256m 밖 청크는 렌더러 가시 여부와 무관하게 세션에서 제거한다. 안개 설정 모듈은 준비됐으며 4D 모드 장면 연결은 런타임 통합 단계에서 진행한다.

## 구현 단계

1. **격리 기반:** 별도 모듈과 열차 저장 키, 청크 좌표, 통로 중력 방향.
2. **세션 월드:** 세션 중 청크 스트리밍·광물 노출·채굴·청크 초기화. 재접속 시 월드 상태는 폐기.
3. **플레이어와 열차:** 구체형 기계, 선두 통합차, 후미 화물차, 길이·소실 위험.
4. **4차원 통로:** 출구/입구, 채굴보다 훨씬 느린 물품 방출, 흡입 이동, 새 출구 청크 생성.
5. **성장·거래:** 레이저 세라믹, 상위 장비, 거래 드론, 고정가·경매 흐름.
6. **복원:** 공유 가능한 암호화 문자열, 인증 이메일 발송, 복원 전 현재 상태 백업 메일.

이메일 발송은 정적 GitHub Pages만으로 안전하게 처리할 수 없으므로 서버 측 발송 경로를 별도로 설계한다.

## 현재 기반과 남은 작업

- 완료: 별도 모듈 경로·열차 저장 키, 16m/0.5m 청크 주소 계산, 음수 좌표 floor 처리.
- 완료: 통로 입구/출구 중력 방향 계산과 청크 거리별 활성·근거리·세션 보존·가시 상태 분류. 64~256m 구간에서 화면에 들어온 청크는 렌더 대상으로 분류한다.
- 완료: 세션 청크 스트리밍 조정기. 32m 이내는 활성, 64m 이내는 근거리 유지, 256m 이내는 비렌더 세션 데이터 보존한다. 256m 밖 청크는 먼지 가림 대상으로 표시하고 렌더러의 가시 여부와 무관하게 세션에서 제거한다. 64~256m의 화면 내 청크는 유지한다.
- 완료: 224~256m 선형 먼지 안개와 4D 전용 Three.js 장면/카메라 설정. 배경색을 먼지색과 맞추고 카메라 원거리 평면을 320m로 둬 안개 경계가 렌더링 범위 안에 들어온다. 기존 광산 장면에는 적용하지 않는다.
- 완료: 청크 렌더 레지스트리와 복셀 표면 메쉬 생성기. 활성/근거리/화면 내 청크만 표시하고, 청크 초기화 때 장면에서 제거하며 지오메트리를 해제한다. 세션 조회 어댑터가 현재 청크의 광물 상태를 메쉬 생성기에 공급하며, 내부 면을 생략하고 재료별 지오메트리를 만든다. 인접 청크는 이미 생성된 경우에만 경계 면 계산에 사용한다.
- 완료: 32m 청크를 8m³ 구역 64개로 나눠 부분 갱신한다. 복셀 채굴 시 복셀이 속한 구역과 인접 복셀이 있는 구역만 다시 만들고, 청크 경계를 넘으면 인접 청크 갱신 좌표를 반환한다.
- 완료: 재접속 전용 기억 암시 대사 선택기. 새 게임 시작에서는 대사를 반환하지 않는다.
- 완료: 런타임 메모리에만 보관되는 세션 청크 상태. 노출 광물은 65/18/10/5/2 비율로 첫 노출 때 정하고, 세션 내 채굴 중복 보상을 막는다. 청크 초기화와 대형 통로 이동 시 기록을 비운다. 이 상태는 저장 키·월드 시드 없이 재접속 간 유지되지 않는다.
- 완료: 구체형 기계용 구-복셀 충돌 해결 함수. 현재 세션에 생성된 단단한 복셀만 대상으로 하며, 채굴된 복셀과 미생성 청크는 빈 공간으로 처리한다. 겹칠 경우 구체를 표면 바깥으로 밀어내고 접촉 방향을 반환한다.
- 완료: 4D 런타임 조정기. 프레임마다 플레이어 청크를 준비하고 거리/가시성에 따라 장면을 갱신한다. 채굴 시 광물을 한 번만 지급하고 영향받은 구역 및 로드된 인접 청크 메쉬를 갱신한다. 구체 충돌 질의와 대형 통로 전환에 따른 월드 초기화도 연결한다.
- 다음: 실제 입력·자동 채굴·이동 물리 업데이트를 런타임에 연결하고, 보상과 열차 저장을 원자적으로 통합한다. 채굴 보상을 열차 저장과 연결하고, 구체형 기계 이동·중력 물리와 열차/화물/통로 런타임 통합을 진행한다. 채굴 보상을 열차 저장과 연결하고, 구체형 기계 이동·중력 물리와 열차/화물/통로 런타임 통합을 진행한다.
- 검증 상태: TypeScript 빌드·자동 테스트·브라우저 실행·Pages 배포는 아직 하지 않았다. `main`과 기존 게임 저장은 변경하지 않았다.
