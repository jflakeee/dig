# DIG 4차원 무한 채굴 모드 구현 착수

기준 브랜치: `main` (기존 4개 광산과 공개 Pages 유지)  
작업 브랜치: `feat/dig-4d-mode-foundation-20261124`

## 구현 판단

현재 플레이 가능한 결과물은 제한 크기 복셀 광산을 중심으로 동작한다. 무한 청크, 4차원 통로 콘텐츠, 열차·화물, 거래 드론, 복원 코드 UI는 아직 기존 런타임에 연결되어 있지 않다. 기존 런타임을 통째로 교체하지 않고 **별도 모드**로 추가한다.

재사용 후보: Three.js 렌더러·모바일 입력·오디오·자동 채굴 상태 전이·기계 대사·추진 계산.  
새로 설계할 핵심: 세션 한정 청크 스트리밍, 구체형 기계, 열차와 화물, 포털 중력, 4차원 물품 방출, 거래·백업.

## 세계와 기억 설정

- 플레이어는 사람이 아닌, 드릴·작업등·연구·제조 기능을 내장한 인공지능 구체형 채굴 기계다.
- 플레이어 기계는 인공지능이며, 기억력 문제는 빠진 기억·엇갈린 회상·익숙함을 설명하지 못하는 반응으로 암시한다. 인간이었다는 과거를 사실로 단정하거나 기억 문제를 별도 시스템 데이터 손상과 혼동하지 않는다.
- 채굴 공간은 우주의 물건과 잔해가 모이는 미지의 공간이다. 외계 물질은 미래 지구에서 개발된 것이며, 외계 생물은 우주에 적응하며 진화한 지구 생물의 후손이다. 모든 블록이 물건을 주는 것은 아니며 후보별 확률과 세부 콘텐츠는 후속 설계다.
- 포탈은 서로 다른 공간과 시간대를 연결한다. 소형 드론은 외계 존재처럼 보이는 다른 채굴 기계와의 거래를 중계한다. 매매 가격은 무작위로 변하고 경매는 다른 시간대 상대의 비동기 입찰로 진행한다. 세부 가격 범위·입찰·정산 규칙은 미정이다.
- 월드는 플레이어가 접근할 때 청크 단위로 생성한다. 숨은 블록의 광물이나 아이템은 미리 배정하지 않고 채굴로 처음 노출되어 보이는 순간 결과를 판정해 같은 세션에서 유지한다. 물리적 매점·상점 건물은 두지 않고 거래는 메뉴와 소형 드론으로 연결한다.
- 청크 위치와 4차원 통로 연결 관계는 플레이어가 알 수 없다. 고정 월드 시드나 영구 포털 지도를 제공하지 않는다.
- 현재 세션의 월드 청크는 런타임에서만 유지한다. 재접속하면 주변 환경·현재 위치·통로 연결 기록을 복구하지 않고 새 환경에서 시작한다.
- 포탈을 통해 완전히 다른 청크로 이동할 때는 열차가 빠져나온 뒤 이전 청크 환경과 위치 기록을 버리고, 알 수 없는 위치에 새 환경을 생성한다.
- 열차에 실린 장비·인벤토리·연구·도감 등 진행 데이터는 환경과 분리해 유지한다. 열차에 싣지 않은 물품은 환경 초기화 때 사라진다.
- 새 게임 시작 인트로에는 서사 설명을 넣지 않는다. 이후 솔로 플레이 중 특정 발견·포탈 관측·거래 단서에서 온라인 모드의 숨겨진 세계관을 간헐적인 짧은 대사로 암시한다. 정체를 직접 확정하지 않고, 대사 반복·조작 방해를 막도록 낮은 빈도와 재사용 대기시간을 둔다.
- 재접속 시에는 위 단서 대사와 구분되는 짧은 독백으로 기억이 온전하지 않음을 암시한다. 예: “열차는 그대로인데… 여긴 처음 보는 곳 같아.”

## 성능과 청크 초기화 정책

시야는 청크 길이인 16m를 넘지 않고, 먼지는 거리에 따라 짙어져 그 너머를 가린다. 낮은 성능 기기는 메시 분할/해제와 효과 품질로 최적화한다. 아래의 과거 224~256m 안개 및 256m 초기화는 최신 시야/포탈 전환 규칙으로 대체됐다.

포탈을 통과해 완전히 다른 청크로 이동하면 열차 전체가 빠져나온 시점에 이전 청크가 무너지고 그 청크의 지형·광물·아이템·통로 기록을 초기화한다. 물리 열차가 청크 밖에 남는 경우 차량과 화물이 소실될 수 있다. 열차 안전 길이는 청크 한 변(16m) 이내다.

## 구현 단계

1. **격리 기반:** 별도 모듈과 열차 저장 키, 청크 좌표, 통로 중력 방향.
2. **세션 월드:** 세션 중 청크 스트리밍·광물 노출·채굴·청크 초기화. 재접속 시 월드 상태는 폐기.
3. **플레이어와 열차:** 구체형 기계, 선두 통합차, 후미 화물차, 길이·소실 위험.
4. **4차원 통로:** 출구/입구, 채굴보다 훨씬 느린 물품 방출, 흡입 이동, 새 출구 청크 생성.
5. **성장·거래:** 레이저 세라믹, 상위 장비, 거래 드론, 고정가·경매 흐름.
6. **복원:** 공유 복원 코드 입력과 검증, 현재 열차 진행을 백업 코드로 인코딩해 클립보드에 복사, 복사 성공을 확인한 뒤에만 복원 저장.

이메일 인증·발송과 암호화 키는 사용하지 않는다. 복원 코드는 DIG4R1 형식의 Base64URL 난독화 문자열이며, CRC32 체크섬은 전송 중 우발적 손상만 감지한다. 코드는 비밀이나 변조 방지 수단이 아니며 누구나 읽고 수정할 수 있다. 내용은 열차 진행만 담고 월드·위치·통로 기록은 제외한다.

## 현재 기반과 남은 작업

### 2026-11-25 시작 장면·조명 재검토 결정

- 첫 프레임부터 기계는 어두운 지하에 있다. 캐릭터 충돌 반경에 필요한 최소한의 빈 공간만 두고, 상·하·좌·우·앞·뒤의 여섯 축 방향을 광물층 암반으로 막는다. 넓은 시작 공동과 미리 뚫린 전방 터널은 만들지 않는다.
- 초기 빈 공간은 기계가 벽과 겹치지 않는 최소 크기로 계산한다. 현재 충돌 반경 0.32m와 복셀 한 변 0.5m 기준으로 2×2×2 복셀(1m 정육면체) 시작 공간이 구현 후보이며, 실제 충돌 검증 전에는 확정값으로 취급하지 않는다.
- 배경과 주변광은 계속 어둡게 둔다. 작업등 빔이 닿는 암반·먼지만 제한적으로 보이며, 오프닝 밝기 상승이 있더라도 빔 밝기만 바꾼다. 오프닝 후에도 전역 조명으로 밝아지지 않는다.
- 암반을 제거할수록 작업등 앞쪽에 새 공간이 드러난다. 시점을 돌려 상하좌우·뒤를 보아도 암반이 이어지고, 채굴하지 않은 면은 어둠 속에 남는다.
- 현재 `src/digMode/main.ts`는 5×5×5 복셀 시작 공동과 전방 터널을 미리 비우고, 주변광을 0.04에서 0.54로 높인다. 이 동작은 최신 설계와 다르므로 미구현으로 처리한다. 작업등 외의 주변광이 화면을 밝히지 않도록 조정하고 여섯 방향의 밀폐 시작 상태를 구현해야 한다.
- 어두운 장면에서도 드릴·광물 판별과 메뉴/HUD 가독성을 확보하되 UI가 지하 공간을 비추는 광원처럼 보이지 않게 한다. 통로 센서·희귀 발견 연출도 주변을 상시 밝히지 않는다.

이 결정은 아래의 기존 오프닝 프로토타입 설명을 대체한다.

### 2026-11-25 플레이어·제작·포탈 규칙

- 기본 장비 레이저는 광물과 먼지를 분해해 기본 활동 에너지와 기초 재료를 얻는다. 레이저로 드릴 강화 및 추가 드릴 제작·장착이 가능하다.
- 드릴은 사용 중 확률적으로 손상될 수 있고 수리는 재료를 소비한다. 내구도·확률·비용은 미정. 내구도 0이며 수리 재료가 없으면 레이저로 느리게 긴급 채굴해 수리 재료를 마련한다.
- 기본 광물을 레이저로 가열해 세라믹 장비를 제작한다. 세라믹은 상위 장비 강화 재료로 폭넓게 사용하며, 모든 광물은 장비 제작과 강화 재료가 될 수 있다.
- 새 물품을 식별하면 발견 도감/조감도 목록에 추가한다. 연구·목록 데이터는 손상된 기억과 별개로 유지한다.
- 화물칸은 추가할 수 있고 전체 열차 길이는 청크 길이(16m)가 안전 한계다. 이를 넘기면 청크 붕괴 시 후미가 남아 소실될 위험이 있다.
- 새 청크에 포탈이 확률적으로 존재한다. 입구/출구가 쌍을 이루고 위치는 알 수 없다. 접근 중 중력이 플레이어와 열차를 끌어당긴다. 입구는 먼지·광물·아이템·플레이어가 통과하고, 출구는 먼지를 계속 내보내며 광물·아이템을 채굴보다 낮은 확률로 방출한다.
- 포탈 출현률·중력 범위/세기·출구 방출 확률/간격은 미정이다. 이전 소형/대형 포탈 확률 체계는 이 입구/출구 설계에 맞춰 재결정해야 한다.

이 규칙은 아래의 기존 구현 상태를 갱신하며, 아래 코드 설명은 실제 반영 여부를 나타낸다.

아래의 '완료'는 해당 브랜치에 코드나 독립 모듈이 있다는 뜻이며, 통합 플레이 검증·자동 테스트·배포 성공을 뜻하지 않는다. 미검증 상태는 마지막 검증 항목에서 별도로 관리한다.

- 완료: 별도 모듈 경로·열차 저장 키, 16m/0.5m 청크 주소 계산, 음수 좌표 floor 처리.
- 완료: 통로 입구/출구 중력 방향 계산과 청크 거리별 활성·근거리·세션 보존·가시 상태 분류. 64~256m 구간에서 화면에 들어온 청크는 렌더 대상으로 분류하고, 보이지 않는 청크 메쉬는 해제해 상태 기록만 보존한다.
- 기존 구현: 청크 스트리밍은 32m 활성·64m 근거리·256m 세션 보존/초기화 기준이다. 최신 설계의 16m 시야·포탈 전환 즉시 이전 청크 붕괴와 다르다.
- 기존 구현: 224~256m 선형 먼지 안개, 320m 카메라 원거리 평면. 최신 16m 시야 기준으로 축소·조정해야 한다.
- 완료: 청크 렌더 레지스트리와 복셀 표면 메쉬 생성기. 활성/근거리/화면 내 청크만 표시하고, 청크 초기화 때 장면에서 제거하며 지오메트리를 해제한다. 세션 조회 어댑터가 현재 청크의 광물 상태를 메쉬 생성기에 공급하며, 내부 면을 생략하고 재료별 지오메트리를 만든다. 인접 청크는 이미 생성된 경우에만 경계 면 계산에 사용한다.
- 완료: 32m 청크를 8m³ 구역 64개로 나눠 부분 갱신한다. 복셀 채굴 시 복셀이 속한 구역과 인접 복셀이 있는 구역만 다시 만들고, 청크 경계를 넘으면 인접 청크 갱신 좌표를 반환한다.
- 완료(기억 암시 기반): 재접속 전용 대사 선택기가 있다. 새 게임 시작에서는 재접속 대사를 반환하지 않는다. 단, 최신 설계가 추가한 솔로 플레이 중 세계관 단서 대사는 별도 트리거/선택기/UI 연결이 필요하다.
- 현재 구현: 세션 청크 상태는 메모리에만 보관되고 5종 광물을 관리한다. 메시 생성기가 모든 복셀을 조회할 때 `exposeVoxel()`로 광물을 미리 판정하여 채굴 최초 노출 시 생성 규칙과 다르다. 일반 물건·외계 물체·생물 잔해 보상 및 발견 도감 연결도 없다.
- 완료: 구체형 기계용 구-복셀 충돌 해결 함수. 현재 세션에 생성된 단단한 복셀만 대상으로 하며, 채굴된 복셀과 미생성 청크는 빈 공간으로 처리한다. 겹칠 경우 구체를 표면 바깥으로 밀어내고 접촉 방향을 반환한다.
- 완료: 4D 런타임 조정기. 프레임마다 플레이어 청크를 준비하고 거리/가시성에 따라 장면을 갱신한다. 채굴 시 광물을 한 번만 지급하고 영향받은 구역 및 로드된 인접 청크 메쉬를 갱신한다. 구체 충돌 질의와 대형 통로 전환에 따른 월드 초기화도 연결한다.
- 완료: 런타임 자동 채굴 상태 전이와 무중력 추진 이동. 통로 필드는 설정된 범위 안에서 중력 가속도를 주며, 입구는 통로 안쪽, 출구는 반대 방향으로 작용한다. 범위 바깥이나 통로가 없는 청크는 무중력이고, 가속도는 범위 경계에서 0으로 부드럽게 감소한다. 실제 조작 입력과 장비별 가속도/최고 속도는 호출자가 전달한다.

## 2026-11-24 재검토: 복원 설계와 남은 작업

### 복원 코드 흐름

1. 사용자가 붙여 넣은 코드를 디코드하고 TrainSaveState 스키마로 검증한다.
2. 복원 직전 현재 열차 상태를 다시 읽어 백업 코드를 만든다.
3. 사용자의 복원 버튼 동작 안에서 Clipboard API로 백업 코드를 복사한다.
4. 코드 복사와 최신 저장 상태 확인이 성공한 경우에만 가져온 상태를 저장한다. 복사 실패나 저장 충돌이면 기존 저장을 유지하고 실패 사유를 화면에 알린다.
5. 백업 코드를 다시 디코드해 스키마와 데이터가 원본 snapshot과 일치하는지 확인한다. 월드 청크, 위치, 통로 연결과 시드는 복원 코드에 넣지 않는다.

자동 복사 실패 시 수동 복사 fallback을 보여주며, 사용자가 확인하기 전에는 복원을 저장하지 않는다. 브라우저 clipboard 권한이 거부되어도 기존 저장은 유지된다.

복원 코드는 이메일·메일박스 검증이나 서버 키에 의존하지 않는다. DIG4R1 버전 표식과 Base64URL payload를 사용하며 CRC32는 우발적 손상만 찾는다. 암호화나 악의적 수정 방지는 제공하지 않으며, 이 코드는 공유용 게임 진행 데이터로 취급한다.

### 나머지 미구현 항목

- **복원 UI/서비스 검증:** 복사·붙여넣기·복원 UI와 codec/clipboard 서비스가 4D 진입 화면에 연결되었다. 자동/수동 복사 실패, 잘못된 코드, 너무 큰 코드, 복원 성공·실패 안내의 실제 브라우저 검증은 남아 있다.
- **저장 동시성:** 복원 직전 snapshot/revision을 읽고 저장 직전 다시 비교한다. 4D 페이지의 일반 저장과 복원 저장은 같은 Web Lock 이름을 사용하며, 저장 모듈의 baseline 충돌 검사도 유지한다. 다중 탭 경쟁 검증은 남아 있다.
- **백업 신뢰성:** 백업 코드를 다시 디코드해 snapshot과 비교하며 CRC32로 전송 손상을 감지한다. CRC32는 악의적인 수정이나 조작을 막지 않는다. 코드 변조 시 열차 진행을 임의로 바꿀 수 있다.
- **연구·도감:** 저장 스키마에 research와 codex 식별자만 있다. 해금 조건, 콘텐츠, 화면, 보상은 구현되지 않았다.
- **4D 통로:** portalGravity.ts와 런타임의 통로 중력 입력은 있지만, 통로 생성·발견·입출구 배치·흡입 이동·새 출구 생성 및 물품 방출은 완성된 플레이 흐름으로 연결되지 않았다.
- **열차·화물:** 현재 별도 페이지의 드릴 강화·드릴 수·열차 인벤토리 저장은 기반 수준이다. 선두 통합차/후미 화물차 표현, 적재 용량, 열차 길이와 소실 규칙, 열차 관리 UI는 미구현이다.
- **성장·거래:** 레이저 세라믹과 상위 장비, 거래 드론, 무작위 변동 매매 가격, 다른 시간대 채굴 기계와의 비동기 경매는 미구현이다.
- **검증·배포:** 변경 후 TypeScript 빌드, 자동 테스트, 브라우저 및 모바일 플레이 검증이 필요하다. GitHub Pages는 main 배포이므로 이 브랜치 내용은 병합 전까지 공개 주소에 나타나지 않는다.

## 2026-11-24 재검토: 통로 생성과 물리 규칙

### 확정된 규칙

- 새 청크가 생성될 때 대형 통로는 3%, 소형 통로는 10% 확률로 존재 여부를 판정한다.
- 플레이어가 해당 청크에 진입하면 통로 주변의 미세중력을 센서로 감지하고 표시한다.
- 소형 통로는 광물과 소형 드론만 통과할 수 있고, 대형 통로는 채굴 기계와 열차가 통과할 수 있다.
- 통로는 입구/출구 한 쌍이며 한 방향으로만 이동한다. 통과는 순간이동이 아니라 물리적으로 끌려 들어가 반대편으로 빠져나오는 흐름이다.
- 입구 주변의 중력 효과는 먼지·광물·드론·채굴 기계·열차를 끌어당기는 물리 효과로 표현한다. 별도 순간이동 입력이나 강제 위치 스냅은 사용하지 않는다.
- 열차 전체가 통과하면 이전 청크 환경을 초기화한다. 출구에서는 가끔 광물 또는 장비가 떨어진다.
- 현재 구현 기반은 통로 필드의 가속도 계산과 채굴 기계 이동뿐이다. 먼지·광물·드론·열차의 관성, 충돌, 마찰과 통로 통과 처리는 미구현이다.

### 다음 구현 단위

1. 세션 청크 생성 시 소형/대형 통로 후보를 확률 판정하고 쌍의 방향 및 입출구 데이터를 런타임 전용으로 보관한다.
2. 청크 진입 시 센서가 근처 통로 중력 신호를 표시한다.
3. 통로 중력장을 물체 시뮬레이션에 적용한다. 우선 기계·열차·드론은 고정 단계의 물리 업데이트와 복셀 충돌을 사용하고, 먼지·광물은 묶음/저비용 업데이트로 모바일 성능을 제한한다.
4. 통로를 실제로 통과한 열차 꼬리가 출구를 완전히 벗어난 뒤에만 이전 청크를 초기화한다.
5. 출구 방출 광물/장비는 낮은 빈도로 생성하고 회수 여부를 열차 인벤토리에 반영한다.

“무작위” 응답은 소형·대형 통로 생성 판정의 관계인지 통로 방향 선택인지 명확하지 않아, 독립 판정/한 청크당 하나 제한/통로 방향 중 어느 규칙인지 아직 고정하지 않는다. 방향·확률 계산은 이 선택에 맞춰 테스트한다.
