# 원소 118종 획득 경로 보완 설계 · 2026-11-26

[광물 16종 확장안](dig-mineral-catalog-expansion.md)의 「원소 분해와 민감 시료 수집」을 보완한다. 기존 설계는 원소를 시료 조성으로 결정하고, 미래 원소 표본 캡슐이 1–118번 전부를 공급한다는 원칙만 정했다. 문서에 조성이 적힌 시료는 석영·고령석·얼음·수소·진사·수은뿐이어서 자연 경로로 얻는 원소는 약 20종이고, 나머지 약 98종은 캡슐 한 경로에 몰려 있었다.

이 문서는 다음 세 경로로 118종을 나눈다. 기본 광물의 다섯 행 확률(암석 65·석탄 18·철 10·금 5·희귀 2)과 동반 광물 확률은 바꾸지 않는다. 세부종 비율, 희소 가중치, 발생률, 보정 규칙은 **밸런스 검증 전 시험값**이다.

| 경로 | 공급 원소 | 획득 방식 |
| --- | ---: | --- |
| ① 기본 16종 광물의 세부종 | 21종 | 기존 채굴 산출. 세부종은 블록 노출 키로 고정 |
| ② 광물 시료 발견물 | 67종 추가 (자연 경로 합계 88종) | 기존 독립 추가 발견 판정의 광물 시료 풀 |
| ③ 미래 원소 캡슐 | 캡슐 전용 30종 (캡슐 자체는 1–118 전부 후보) | 같은 추가 발견 판정의 캡슐 풀 |

캡슐 전용 30종은 자연에서 실제로 채굴할 수 없거나 존재량이 극미한 원소다: Tc, Pm, At, Fr, Np, Pu와 95번(Am)–118번(Og). 나머지 88종은 실제 광물·포유물 조성에서 나온다.

## 1. 기본 16종 광물의 세부종과 조성

**구현 상태(2026-11-26, `next/`).** 이 절의 세부종 비율과 원소 단위표는 `next/minerals.js`의 `variants`에, 원소 기호 118종은 `next/elements.js`에 있다. 채굴한 광물은 세부종과 함께 저장된다(저장 버전 4). 저장에는 기본이 아닌 세부종 수량만 `variants`에 적고, 광물 총량에서 이를 뺀 나머지를 첫 세부종으로 계산한다. 그래서 기존 수량은 변환 없이 첫 세부종이 된다. 암석을 쓰는 제작·가열은 첫 세부종부터 차감한다. 메뉴에는 세부종별 수량이 보인다. 메뉴의 분해기는 보유한 세부종을 골라 원소 산출을 미리 보여준 뒤 1개를 분해한다. 원료 차감, 원소 지급, 원소 도감 최초 등록은 한 저장에 기록된다(저장 버전 5, `elements`·`elementLog`).

## 2. 광물 시료 발견물

**구현 상태(2026-11-26, `next/`).** 2–4절의 시료 47종, 캡슐 가중치와 미등록 보장, 발생률은 `next/specimens.js`에 있다. 드릴 장착 후 채굴한 블록마다 셀 키로 추가 발견을 판정한다. 시료와 캡슐은 그 블록의 작업 키를 개체 ID로 써서 저장한다(저장 버전 6). 캡슐 원소는 블록을 지급하는 순간의 원소 도감을 기준으로 정한다. 수소·희가스 포유물과 자연 수은 방울은 6초 포집 대기열에 들어가며, 마감 시각과 같거나 늦은 입력은 소실로 처리한다. 다른 공간으로 이동하거나 재기동하면 대기 중인 시료는 남겨 두고 떠난다. 분해기에서 시료와 캡슐도 분해할 수 있다. 추가 발견의 나머지 35%는 [비광물 발견물 24종](dig-nonmineral-finds.md)이다. 원소 캡슐의 압력·열 민감 형태는 아직 없다.

## 3. 미래 원소 캡슐

캡슐은 원소 1종을 봉인한 표본이고, 외피는 원소 보상에서 제외한다. 후보는 1–118번 전부이며 가중치는 다음과 같다.

| 조건 | 가중치 |
| --- | ---: |
| 캡슐 전용 30종 | 3 |
| 그 밖의 88종 | 1 |
| 이미 원소 도감에 등록된 원소 | 위 값 × 0.25 |

**미등록 보장**: 캡슐이 연속 10개 등록된 원소만 냈다면, 다음 캡슐은 미등록 원소 중에서 균등 추첨한다. 새 원소가 나오면 연속 횟수를 0으로 되돌린다. 연속 횟수는 저장한다. 캡슐 내용은 노출 시 확정되므로, 같은 블록을 다시 요청해도 다시 추첨하지 않는다.

압력 캡슐·에너지 결정 같은 민감 형태는 기존 표(완충 4초, 차열 5초)를 따른다. 위험 형태는 원소가 아니라 캡슐 종류로 정한다.

## 4. 발생률과 예상 수집 시간

드릴 장착 후 채굴한 블록마다 독립 추가 발견 판정을 한 번 한다.

| 항목 | 시험값 |
| --- | ---: |
| 추가 발견 발생 | 블록당 2% |
| 발생 시 광물 시료 | 60% (블록당 1.2%) |
| 발생 시 장비·미지 물질·생활물품 24종 | 35% ([비광물 발견물](dig-nonmineral-finds.md)) |
| 발생 시 미래 원소 캡슐 | 5% (블록당 0.1%) |

시험값으로 40회 모의 실행한 결과(얻은 시료는 모두 분해한다고 가정)는 다음과 같다.

| 조건 | 118종 완성까지 채굴 블록 (중앙값) | 10–90% 범위 |

| 위 보정 적용 | 약 9.7만 | 7.4만–12.0만 |
| 보정 없음(가중치 모두 1, 보장 없음) | 약 24만 | 90%가 32.6만 이내 |

보정을 적용하면 자연 경로 88종과 캡슐 전용 30종이 비슷한 시점(각 약 8.5만 블록)에 완성되어, 한 경로만 늦게 남는 구간이 줄어든다. 시험판에서 관측한 초당 약 3.5블록으로 환산하면 중앙값은 순수 채굴 약 8시간이다. 목표 시간이 정해지면 발생률만 조정한다.

## 5. 저장·분해 계약

1. **세부종 키.** 인벤토리는 세부종 단위로 센다(예: `iron:hematite`, `rock:granite`). 저장 버전을 올릴 때 기존 수량은 각 광물의 첫 세부종(화강암, 적철석 등)으로 한 번만 옮긴다. 일반 암석의 기존 `rocks` 수량도 화강암으로 본다.
2. **시료 개체.** 광물 시료와 캡슐은 개체 ID·카탈로그 버전·세부종·상태(봉인·누출·소실)를 저장한다. 같은 블록의 시료는 셀 작업 키로 한 번만 지급한다.
3. **분해.** 원료 1개 차감과 원소 지급, 원소 도감 최초 등록을 한 저장에 기록한다. 제작에 이미 쓴 원료나 소실된 시료는 분해 목록에서 뺀다. 분해 미리보기는 표의 게임 원소 단위를 그대로 보여준다.
4. **원소 인벤토리.** 기호별 정수 수량과 최초 등록 순서를 저장한다. 원소 키는 1–118 표준 기호만 허용한다.

## 7. 구현 순서와 검사 항목

1. 기본 16종 세부종과 원소 단위표를 데이터로 추가하고, 저장 버전 변환을 구현한다.
2. 원소 인벤토리와 분해(미리보기 → 확정)를 붙인다.
3. 추가 발견 판정에 광물 시료 풀과 캡슐 풀을 연결하고, 기존 민감 시료 경고와 정산을 재사용한다.
4. 검사:
   - 1–118 기호의 중복·누락 확인. 캡슐 전용 30종과 자연 경로 88종이 겹치지 않고 합이 118인지 확인
   - 모든 원소에 최소 한 개의 양수 가중치 경로가 있는지 확인
   - 세부종·시료·캡슐을 고정 난수로 뽑아 각 구간의 양 끝 확인
   - 캡슐 미등록 보장 10회 경계 확인
   - 분해 1회 차감·지급, 재요청·재접속 시 이중 지급 없음 확인
   - 기존 저장의 수량이 대표 세부종으로 한 번만 옮겨지는지 확인
