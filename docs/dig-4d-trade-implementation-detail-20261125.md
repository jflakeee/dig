## 1. 목적과 범위

매점 건물 없이 소형 드론이 플레이어 기계와 다른 채굴기계를 연결한다. 다른 기계는 플레이어 관점에서 외계 존재처럼 보이지만 포탈을 통해 다른 장소·시간대에 존재한다. 매매 시세는 무작위로 변하고, 경매는 다른 시간대의 기계들이 비동기적으로 입찰하는 방식이다.

현재 싱글플레이 구현은 통신 상대를 세계관상 실재하는 다른 채굴기계로 표현하되, 입찰·가격 반응은 로컬 시뮬레이션으로 처리한다. 이 설계가 실제 온라인 접속, 다른 이용자의 실시간 참여, 서버 거래를 뜻하지는 않는다. 온라인 모드에서 상대를 실제 플레이어/서버로 연결할 수 있도록 주문·정산 계약을 분리한다.

## 2. 거래 원칙

- 소형 드론은 통신 중계기이며 상점이나 거래 당사자가 아니다. 화면에는 상대 채굴기계의 신호/기계 식별 표식을 보여준다.
- 가격이 표시되는 물품은 즉시 매입·판매가 가능하다. 가격이 없는 물품은 경매로 등록한다.
- 매입가와 판매가는 같은 품목이어도 다를 수 있다. 같은 시장 주기 안에서 UI를 다시 열거나 새로고침해도 가격이 재추첨되지 않는다.
- 매매가는 시장 주기, 상대 기계의 선호, 공급/수요에 따라 무작위로 변한다. 변동 폭·통화 명칭·초기 자금은 조정 설정값으로 두며 이 문서에서 밸런스 수치를 고정하지 않는다.
- 경매 상대는 서로 다른 시간대의 채굴기계다. 등록 직후 끝나는 고정가 구매가 아니라, 일정 시간 동안 제안을 받고 종료 후 최고 유효 입찰로 정산한다.
- 개인 기억 연출, 발견 도감, 청크 좌표는 거래 정산과 분리한다. 물품·통화·주문 상태만 거래 저장 데이터에 기록한다.

## 3. 물품 거래 가능 상태

| 물품 상태 | 가능한 행동 | 세부 규칙 |
| --- | --- | --- |
| 매매가가 표시된 소지품 | 즉시 판매 | 상대 기계가 매입하고 플레이어가 통화를 받음 |
| 매매가가 표시된 시장 품목 | 즉시 구매 | 플레이어가 통화를 내고 물품을 받음 |
| 가격이 미지정된 발견물/특수 화물 | 경매 등록 | 보관품을 주문 에스크로로 옮기고 시간대 상대의 입찰을 받음 |
| 거래 제한/미확인 상태 | 분석/보관 | 물품을 임의로 자동 판매·경매하지 않음 |

분석되지 않은 물품의 정체·가격은 자동으로 노출하지 않는다. 사용자가 도감 등록 등 필요한 확인 절차를 마친 뒤 시장 견적을 받을 수 있다. 세라믹 재료나 장비처럼 제작에 사용할 물품도 플레이어가 선택하지 않는 한 자동으로 처분하지 않는다.

중고 장비의 개체 상태, 미지 물질의 경매, 생활물품의 분해·판매 선택은 [비광물 발견물 24종](dig-nonmineral-finds.md)을 참조한다.

## 4. 변동 시세 산정

### 4.1 견적 데이터

견적은 다음 조합으로 고정한다.

`quoteKey = marketCycleId + traderProfileId + itemId + side`

`price = baseValue × conditionFactor × traderPreference × demandFactor × supplyFactor × randomFactor`

- `baseValue`: 물품 콘텐츠의 기준 가치. 없는 물품은 매매 견적 대신 경매 대상으로 분류한다.
- `traderPreference`: 상대 채굴기계의 수집/제작 선호. 상대 프로필별 고정 가중치다.
- `demandFactor`, `supplyFactor`: 현재 시장 주기의 재고와 거래량을 반영한다.
- `randomFactor`: 해당 견적 키의 시드에서 산출한다. 같은 시장 주기와 품목/상대/매매 방향에는 같은 값이 나온다.
- `side`: 매입/판매 견적을 분리해 매수·매도 차이를 둔다. 정확한 차이는 밸런스 설정으로 관리한다.

가격은 시장 주기가 바뀔 때 재산정한다. 시장 주기는 게임 내 거래 시계로 진행하며, 거래 패널을 반복해서 열어도 주기를 강제로 넘기지 못한다. 상대 기계 프로필과 시장 주기 시드는 세션 데이터에 저장해 화면 갱신·재접속으로 가격 재추첨이 되지 않게 한다. 시스템 시계 조작은 시세에 쓰지 않는다.

### 4.2 UI에 표시할 값

각 품목 행에 품목명/식별 상태, 보유량, 상대 매입가, 상대 판매가, 견적 유효 시장 주기를 표시한다. 사용자가 거래 수량을 선택하면 총액과 거래 후 보유량/통화를 확인 버튼에 미리 보여 준다. 변동 시세가 갱신되면 확인 전에 새 총액을 다시 동의받는다.

상대의 표식·통신 잡음·말투는 시간대가 다른 채굴기계라는 서사를 전달할 수 있지만 실제 계산식이나 확률을 감추어 조작하지 않는다.

## 5. 즉시 매매 트랜잭션

1. 거래 버튼을 누르면 현재 인벤토리, 통화, 시장 주기, 견적 revision을 읽는다.
2. 해당 시점의 견적과 수량으로 미리보기 총액을 계산한다.
3. 사용자가 확정하면 저장 잠금/원자적 revision 검사로 최신 인벤토리와 견적을 다시 확인한다.
4. 판매는 보유 물품을 차감하고 통화를 더한다. 구매는 통화를 차감하고 물품을 더한다.
5. 지갑·인벤토리·거래 장부를 한 트랜잭션으로 저장한다. 어떤 쓰기라도 실패하면 전체 변경을 취소한다.
6. 동일 `transactionId` 재시도는 이전 결과를 반환하고 다시 차감/지급하지 않는다.
7. 저장 충돌이 있으면 거래를 거절하고 새 견적/수량을 다시 표시한다.

한 번에 거래 가능한 수량은 보유량, 화물칸 여유, 상대 재고/예산 중 최솟값이다. 구매 후 적재 공간이 부족하면 구매를 확정할 수 없다. 거래 실행 중 채굴·자동 전진은 멈추고, 완료/취소 후 이전 이동 상태를 안전하게 복구한다.

## 6. 경매 수명주기

`draft → listed → bidding → settled | expired | cancelled`

- **등록:** 물품과 수량을 확인하고 최저 허용 입찰가 또는 자동 시작가 정책을 선택한다. 가격이 없는 물품은 최초 등록 때 시장 상대가 제시한 시작가 추정치를 보여 준다. 등록 확정과 동시에 물품을 에스크로로 이동한다.
- **결과 결정:** 주문 등록 때 저장한 난수 시드와 주문 ID를 사용해 만료 시 결과를 한 번만 결정한다. 결과 범위는 `유찰(0) ~ 등록 기준가의 10배 낙찰`이며, 유찰 또는 낙찰 금액은 무작위로 선택된다. 재접속·재실행으로 결과를 다시 뽑지 않는다.
- **시간대 반응 연출:** 다른 시간대 기계들은 입찰 신호와 가격 반응을 비동기적으로 보낸다. 이 반응은 경매 진행을 보여 주며, 최종 결과는 위 무작위 판정 규칙이 권위 있게 결정한다. 플레이어가 입찰하는 경매의 유효 입찰/예약은 기존 규칙대로 처리하고, 등록 물품의 최종 낙찰 결과는 등록 기준가 대비 10배를 상한으로 한다.
- **플레이어 입찰:** 상대 기계가 등록한 경매에 플레이어도 입찰할 수 있다. 최고 입찰액을 에스크로로 예약해 중복 입찰/지출을 막고, 새 최고가로 교체되거나 낙찰 실패하면 예약액을 풀어 준다.
- **종료:** 게임 내 마감 시각에 시드 기반 무작위 결과를 확정한다. 유찰이면 물품을 반환한다. 낙찰이면 결과 금액은 등록 기준가의 1~10배 범위이며, 등록 기준가와 상한은 주문 생성 시 고정한다.
- **정산:** 낙찰 금액에서 경매 수수료를 차감한 순액을 판매자에게 지급하고, 낙찰 물품을 구매자에게 전달한다. 수수료율은 밸런스 설정값으로 남긴다. 수수료는 낙찰 때만 발생하며 유찰·취소에는 부과하지 않는다.
- **유찰:** 물품은 판매자에게 반환되고 통화 변화와 수수료는 없다. 유찰 결과와 만료 알림을 드론 통신함에 남긴다.
- **취소:** 낙찰 전이고 유효 입찰이 없을 때만 취소 가능하도록 초기 기본 규칙을 둔다. 입찰이 이미 유효하면 시장 신뢰를 위해 취소를 잠근다. 정책 변경은 설정/버전으로 분리한다.

경매 시간은 벽시계가 아니라 게임 내 시장 시계로 측정한다. 솔로에서 게임이 활성화되어 있을 때만 진행되고 앱이 닫혀 있는 동안 상대의 입찰 결과를 임의로 쌓지 않는다. 미래 온라인에서는 서버 시간과 서버 검증된 입찰 로그를 사용하되 같은 상태 전이·정산 계약을 재사용한다.

## 7. 비동기 상대 기계 시뮬레이션

- 각 상대는 `traderProfileId`, 시간대 프로필, 관심 품목, 예산 범위, 입찰 성향, 응답 지연 분포를 가진다.
- 프로필은 거래 시점에만 생성/선택하고 반복 새로고침으로 새로운 상대와 새로운 가격을 무한 생성하지 않는다.
- 경매 결과는 등록 시 저장한 난수 시드와 주문 ID로 재현할 수 있어 재접속/복구 후 결과가 달라지지 않는다. 결과 확정은 주문당 한 번이며, 낙찰 금액은 등록 기준가의 최대 10배이며, 유찰도 결과에 포함된다.
- 입찰을 하지 않는 상대도 존재한다. 희귀품에는 관심 상대가 많을 수 있지만 낙찰 보장이나 숨은 최저가 조작은 하지 않는다.
- 거래 상대의 말투·시대 흔적은 솔로 스토리 단서 이벤트를 발행할 수 있다. 플레이어는 상대가 외계 존재라고 오해할 수 있으나, 직접적인 미래 지구 설명은 하지 않는다.

## 8. 저장 구조와 복원

```ts
export type TradeStateV1 = Readonly<{
  currencyCode: string;
  balance: number;
  marketCycleId: string;
  quoteSeed: string;
  transactions: readonly TradeTransaction[];
  auctions: readonly AuctionOrder[];
  reservedCurrency: number;
  escrowedItems: readonly EscrowItem[];
}>;
```

- 잔액·재고·시장 주기·미정산 주문·에스크로는 버전 있는 거래 저장 네임스페이스에 보관한다.
- 모든 통화/물품 변경은 revision 검사와 거래 ID 멱등성 키를 사용한다. 트랜잭션 장부는 최근 중복 방지에 필요한 범위만 유지한다.
- 공유 복원 코드는 현재 진행을 다른 사람이 체험할 수 있는 코드다. 따라서 거래 잔액/인벤토리 등 공유 대상으로 승인된 진행 값은 함께 복원할 수 있다. 공개하지 않을 미정산 주문은 복원 payload에 포함하지 않고, 복원 전에 주문 목록을 보여 주어 취소/정산 여부를 확인한다. 복원 저장 전에 기존 진행 백업 코드를 클립보드에 복사하는 현재 규칙은 유지한다.
- 저장 실패나 revision 충돌 시 통화·물품·주문 상태 일부만 반영하지 않는다. 복원과 일반 거래는 같은 저장 잠금/직렬화 정책을 따른다.
- 이 코드는 싱글 진행 데이터의 일관성을 위한 것이며, 온라인 통화/경매에는 서버 권위 검증이 필요하다.

## 9. 초기 UI 흐름

1. 조건이 충족될 때만 거래 버튼을 표시한다. 물리 매점 UI는 만들지 않는다.
2. 거래 드론 통신 패널에서 상대 기계 신호와 `매매`/`경매` 탭을 보여 준다.
3. 매매 탭은 매입/판매 목록, 보유량, 양쪽 견적, 수량 선택, 총액 확인을 표시한다.
4. 경매 탭은 진행 중/내 경매/입찰 예정/낙찰·만료 결과를 나누고 마감까지의 게임 내 시간을 보여 준다.
5. 주문이 끝나면 작은 드론 메시지를 표시한다. 채굴 장면과 버튼을 가리거나 자동 이동 중 조작을 막지 않는다.

## 10. 완료 기준과 미정 수치

- 같은 시장 주기 중 같은 품목 견적은 UI 재진입으로 바뀌지 않고, 다음 주기에서 시세가 변할 수 있다.
- 매입/매도 가격은 구분되며, 수량·잔액·화물칸 한도 검사 후 한 번만 정산된다.
- 거래 저장 실패와 중복 클릭/재시도는 중복 지급·중복 차감을 만들지 않는다.
- 가격이 없는 물품은 경매 등록으로 이어지고, 아이템은 주문 종료 전 에스크로에 묶인다.
- 무작위 유찰·최대 10배 낙찰·수수료 정산·취소/저장 충돌/복원 중 주문 처리를 일관되게 복구한다.
- 솔로의 상대는 오프라인 시뮬레이션이고 온라인 연결은 별도 서버 작업으로 남는다.
- 시장 주기 길이, 시세 변동폭, 거래 통화 이름/초기 잔액, 수수료율, 경매 기본 기간·입찰 신호 지연·등록 기준가, 특별 화물 예외는 밸런스 설정값이다. 수치 확정 후에도 거래·정산 계약과 분리한다.
