# DIG 통합판 구현 상세설계 · 2026-11-26

개방된 포탈의 청크 전체 중력, 출구의 미채굴 블록 이탈, 파편 충돌·강제 통과와 치명 피해 후 인트로 복귀는 [포탈 중력·연쇄 붕괴·재기동 상세설계](dig-portal-collapse-and-reboot.md)를 따른다. 사망 시 진행 계승 범위는 미정이다.


대상은 `/dig/next/`다. 기준 코드 `8f60bf6`에는 암석 3개로 첫 드릴 제작, 시야 방향 자동 운행, 메뉴를 연 채 채굴, 일반 청크 경계 통과, 고정 포탈 한 쌍이 있다. 첫 구현 단위는 **실제 한 면을 비운 뒤 예약된 포탈을 통과하는 플레이**다. 광물·위험 시료·화물·거래는 같은 채굴 이벤트와 저장 계약 위에 순서대로 붙인다. 설계 우선순위는 [프로젝트 메모리](PROJECT_MEMORY.md)와 [11월 26일 면 규칙](dig-chunk-faces-and-portals.md)을 따른다.

## 2. 청크와 포탈의 데이터 계약

| 레코드 | 필수 값 | 수명 |
| --- | --- | --- |
| 청크 | 공간 ID, 좌표, 세대, 형태, 지형 시드, 파낸 셀, 면 6개의 상태, 첫 채굴 완료 면 시각, 여섯 이웃 공개 여부 | 한 청크 세대. 좌표만 같은 새 세대는 별개 |
| 면 | 축과 부호, 잔여 고체 수 0~1024, 최초 완료 원인(초기 빈 면/채굴), 완료 시각, 개방 예정 시각, 연결 ID | 한 청크·한 면에 예약 최대 한 건 |
| 포탈 쌍 | 출발 면, 목적지 공간, 입출구 중심·법선·접선 2개, 개구 폭·높이, 활성 상태 | 같은 입구의 렌더·물리·센서에서 공유 |
| 통과 중 편성 | 통과 ID, 쌍 ID, 차량 순서, 차량별 뒤끝 통과 여부, 출발 청크 참조 | 마지막 차량 통과 확정까지 |
| 영구 진행 | 저장 버전과 revision, 드릴과 장착 ID, 화물·도감·연구·주문, 최초 통과 여부 | 청크가 붕괴해도 유지 |

**좌표.** 한 셀은 0.5m다. 현행 좌표식 `floor((cell+15)/32)`을 유지한다. 한 축에서 월드 셀 16은 청크 0의 로컬 31, 17은 청크 1의 로컬 0이다. 블록은 소유 청크의 로컬 좌표가 0 또는 31인 면에만 기여한다. 꼭짓점 한 개를 파면 같은 청크의 세 면이 각각 1씩 감소한다. 맞은편 이웃 셀은 그대로다.

**생성.** 시작은 암반형과 본체 여유 공간을 사용한다. 일반 청크는 좌표·세대 시드로 암반, 공동, 동굴, 부유 창고 중 하나를 뽑는다. 동굴은 시드 기반 점유 함수, 창고는 빈 점유와 발견물 배치 후보로 표현한다. 창고 물품 ID는 첫 관측 때 확정한다. 각 면은 점유 함수로 32×32칸을 세어 초기화하고 이후에는 제거된 셀만 반영한다. 이미 열린 경계를 지나갈 때 다음 청크가 같은 월드 좌표에서 충돌 조회에 참여해야 한다.

## 3. 한 번의 굴착에서 실제 통과까지

1. **채굴 확정.** `mine(epoch, localCell, eventId, expectedRevision)`은 아직 고체인지와 도구 상태를 확인한다. 최초 성공에서만 셀 제거·보상 배치·도구 비용·영향받은 면의 감소를 한 변경 묶음으로 만든다. 레이저 인트로의 암석 수집은 첫 드릴 제작 비용 3개를 유지한다.
2. **면 예약.** 잔여 수가 1→0이 된 각 면에 현재 게임 시각과 `due = now + 300000ms + positiveDelay`를 기록한다. 추가 지연과 크기 추첨에는 면·세대·용도별 시드를 사용한다. 초기부터 빈 면은 첫 실제 진입 때 예약하는 기존 제안안을 적용한다. 미리 로딩한 빈 이웃에서는 타이머를 시작하지 않는다.
3. **여섯 이웃 공개.** 초기 빈 면은 완료 마스크에 포함하고 첫 실제 채굴 완료 면에서 5분 창을 연다. 마지막 채굴 직후 여섯 면이 모두 비고 `last−first ≤ 300000ms`이면 이웃 여섯 좌표를 준비한다. 기존 이웃 변경분을 재사용하고 준비가 끝난 한 틱에 연결 목록을 공개한다. 중간 실패는 누락분만 재시도한다. 이 경로가 면 포탈의 개방 시각을 앞당기지 않는다.
4. **개방.** 표시 프레임 수와 별개인 전경 게임 시계가 예정 시각을 넘으면 쌍 ID로 단 한 번 연다. 메뉴에서도 시간이 흐르고 앱 비활성 시간은 제외한다. 만료 전 센서·개구·흡인은 없다. 여러 면이 동시에 만료되면 모두 활성화한다. 크기 범위에 32×32셀 개구가 실제 후보로 포함되어야 한다. 첫 튜토리얼 입구의 최소 기계 통과 크기는 기존 제안값으로 취급한다.
5. **물리.** 입구 방향으로 이동한 선분이 평면을 가로지르면 교점을 두 접선에 투영한다. 각 축에서 개구 반폭·반높이에서 차량 단면 여유를 뺀 범위 안인지 확인한다. 통과 가능한 개체는 위치·시야·속도를 입구 좌표계에서 출구 좌표계로 변환한다. 인접 청크로 직진한 사건은 포탈 통과로 기록하지 않는다. 먼지는 입구에 흘러들고 출구에서 나온다.
6. **붕괴.** 통과 중 출발 청크는 마지막 차량 뒤끝이 빠질 때까지 보유한다. 정상 완료 후 해당 세대의 입구·예약·바닥 드롭을 폐기한다. 일반 이동 중 거리 붕괴에서는 16m 초과 편성의 실제 잔류 후미 차량과 그 안의 화물만 소실 대상으로 계산한다. 통과 보존과 원거리 소실을 같은 차량에 중복 적용하지 않는다. [편성·화물 상세](dig-4d-train-cargo-chunk-transition-detail-20261125.md)

## 5. 중단·재접속·경합

새 저장 버전은 같은 잠금 안에서 검증 후 한 번에 쓴다. 예전 `rocks=27`은 인벤토리 `rock=27` 한 곳으로 옮기고 드릴 소유·장착·최초 통과 값을 보존한다. 기존 재료와 새 필드를 동시에 합산하지 않는다. 잘못된 저장은 원본을 보존한다. 저장 실패 때는 준비한 변경분을 버리고 기존 월드를 계속 표시한다.

채굴 중 재시도에는 최초 작업 ID를 재사용한다. 같은 세대에서 잠시 언로드한 예약은 원래 시각과 크기를 복구한다. 재접속으로 환경을 새로 여는 정책에서는 새 세션 ID를 발급하고 이전 환경의 예약과 바닥 드롭을 무효화한다. 영구 보상·거래 정산 및 이미 화면에 제시한 민감 시료의 잔여 시간은 별도 기록한다. 복구된 시료는 원래 드롭 ID로 처리하고 같은 바닥 드롭을 재생성하지 않는다. 공유 코드에는 일시적 포탈 연결·목적지 좌표를 넣지 않는다.

두 탭의 같은 블록 요청은 세션·세대·셀 작업 키와 저장 revision으로 확인한다. 이미 완료된 요청에는 기존 결과를 반환한다. 다른 변경과 충돌하면 최신 저장을 읽고 여전히 유효한 요청만 재평가한다. UI 버튼을 닫거나 다시 여는 동작에서는 추첨·결제·손상 처리를 호출하지 않는다.
