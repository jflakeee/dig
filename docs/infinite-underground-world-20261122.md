# DIG — 무한 지하 월드 설계 변경 (2026-11-22)

> 상태: **승인된 설계 방향 기록 / 게임 런타임 미구현**. 이전의 `docs/infinite-chunks-shop-protection-20261122.md`에 정의된 매점 건물·보호구역 및 수평 무한 월드 제안은 이 문서로 **대체**한다. 기존 `main` 배포·저장 데이터는 변경하지 않는다.

## 1. 월드와 시작 위치
- 하늘, 태양광, 지표면, 최상층/최하층 경계를 없앤 **X/Y/Z 3차원 무한 지하 월드**.
- 플레이어 키는 1m, 최소 블록 변 길이는 0.5m로 유지한다.
- 월드 원점 부근 청크 중앙에 안전하게 서 있을 수 있는 작은 시작 공동을 생성한다. 초기 생성 공간은 채굴 가능하되 플레이어가 지형 안에 끼이지 않도록 스폰 검증을 한다.
- 16m × 16m × 16m 청크는 **제안 기본값**이다(0.5m 복셀 기준 축당 32개). 음수 좌표를 포함해 청크 좌표는 floor 나눗셈을 사용한다.
- 월드 생성 시 암석·공동 등 기초 지형을 구성하고, 광물 종류는 아래 노출 이벤트에서 결정한다.
- 하늘빛 대신 램프·광물 발광·인공 조명을 사용한다. 높이는 절대 Y 좌표로 표시한다. 무한 월드에서 부동소수점 정밀도 문제를 피하기 위해 먼 이동 시 렌더 원점을 재설정하는 방안을 검증한다.

## 2. 매점 제거 및 메뉴
- 매점 건물, 매점 플랫폼, 보호 반경, 매점 채굴 금지 로직을 **새 무한 월드 모드에서 제거**한다.
- 판매/구매/강화는 상점 메뉴로 제공하고 위치·고도와 무관하게 접근 가능하게 한다. 제작 메뉴는 유지한다.
- 기존 자원·골드·강화·제작·전설 장비 진행 기록은 보존한다. 지상에서만 거래/제작할 수 있는 기존 제한은 **새 모드에서만** 해제한다.
- 기존 `src/shopProtection.ts`는 초기 검토용 유틸이며 새 모드의 최종 채굴 경로에 연결하지 않는다. 기존 모드와의 호환성을 위해 무조건 삭제하지 않는다.

## 3. 청크 로딩과 초기화
- 플레이어 주변의 가까운 청크만 메모리에 로딩·렌더링한다. 거리 판정은 **3차원 유클리드 거리** 기준으로 청크 경계의 최근접점까지 계산해 경계 깜빡임을 줄인다.
- **제안 거리 기준**: 0–32m 표시/상호작용, 32–64m 렌더링·메모리 해제, 64–256m 변경 기록 유지, 256m 초과 시 청크의 채굴 기록 및 노출 광물 기록 초기화. 경계에 히스테리시스를 두고 한 프레임당 처리량을 제한한다.
- 재방문 시 월드 시드로 기초 지형을 재생성한다. 초기화된 청크는 **새 생성 회차(epoch)** 를 부여해 광물 재추첨을 허용한다.
- 청크 초기화는 플레이어 이동으로 멀어질 때만 수행하며, 세션을 종료했다는 이유만으로 256m 범위 내 기록을 삭제하지 않는다.
- 메모리 해제와 영구 초기화는 별도 동작이다. 메모리 해제만 된 청크의 채굴·광물 기록은 보존한다.
- 기록 삭제는 저장 성공 후 확정한다. 저장 실패 시 이전 변경 기록을 보존한다. 재방문 직전에는 해당 청크의 초기화 epoch 및 변경 상태를 원자적으로 읽는다.
- 256m 초기화는 채굴 흔적을 영구 보존하지 않는 **게임 규칙**이다. 광물 무한 재획득에 따른 경제 밸런스는 별도 검증한다.

## 4. 광물: 사전 배치 대신 노출 시 결정
1. 청크 최초 생성 시 **모든 숨겨진 복셀의 광물 종류를 사전 추첨하지 않는다**. 기본 지층과 공동/고체 상태만 결정한다.
2. 채굴로 고체 복셀이 제거되면 새로 공기에 접한 인접 복셀(최대 6방향)을 탐색한다.
3. 처음 노출된 고체 복셀에만 깊이·지역별 광물 확률표를 적용하여 암석 또는 광물 종류를 결정한다.
4. 이미 결정된 복셀은 청크 메모리 해제, 재로드, 저장·복원 후에도 **동일 종류**를 유지한다. 카메라 시야에 들어왔다는 이유만으로 재추첨하지 않는다.
5. 청크 초기화가 확정되면 노출 광물 결정 기록도 삭제한다. 재방문 후 새 epoch에서 새 노출 이벤트가 일어나면 재추첨한다.
6. 청크 경계의 인접 복셀도 정확히 처리한다. 아직 로딩되지 않은 이웃 청크에는 노출 이벤트를 지연 기록하거나 동일한 결정 함수를 적용하여 누락/중복을 방지한다.
7. 확률 예시(미확정): 일반 암석 65%, 석탄 18%, 철 10%, 금 5%, 희귀 광물 2%. 지역/고도에 따라 달라질 수 있다.

**결정적 난수 키:** `worldSeed + chunkXYZ + localVoxelXYZ + chunkEpoch + lootTableVersion`. 광물 종류는 최초 노출 시 이 키로 결정하고 결과를 기록한다. 같은 epoch에서는 채굴 순서·프레임 속도·재접속에 따라 결과가 바뀌지 않는다. 새로운 epoch는 이전 epoch와 다른 결과를 낼 수 있다.

## 5. 채굴·저장·성능
- 채굴 시간은 기존 기준 대비 3배로 늘리되 도구/강화 효과는 유지한다. 채굴 버튼 누름 주기와 실제 파괴 타이머의 의미를 확인한 뒤 중복 배율을 방지한다.
- 저장: 기존 v1/v2/v3 데이터는 읽기 가능하게 유지하고 신규 무한 월드 저장을 **별도 네임스페이스/버전**으로 추가한다. 좌표·청크 epoch·제거된 복셀·노출 광물 결정을 관리한다.
- 이미 채굴된 광물 보상은 기존 재화·인벤토리 기록과 중복 지급되지 않게 처리한다. 초기화 후 새 광물 재획득은 허용하되 경제 테스트를 통과해야 한다.
- Three.js 청크 메시는 지연 생성하고, 멀어지면 geometry를 dispose 한다. 생성·삭제·노출 광물 결정은 프레임당 예산을 제한한다.
- 플레이어가 위아래로 이동해도 충돌, 조명, 이동, 카메라, UI, 채굴 범위가 정상 작동해야 한다.

## 6. 구현 순서와 검증
1. 신규 월드 모드와 저장 분리; 기존 4개 광산/저장 비파괴.
2. X/Y/Z 청크 생성·해제·초기화 및 음수 좌표/원점 이동 검증.
3. 시작 공동과 충돌·조명·무한 상하 이동 구현.
4. 매점 오브젝트 제거, 상점/제작/강화 메뉴로 전환.
5. 최초 노출 시 광물 결정·청크 경계 처리·epoch 기반 재생성 구현.
6. 채굴 시간 3배, 중복 보상/저장 충돌 방지.
7. Node/TypeScript/Chromium 회귀 테스트, 모바일 가로·세로·장시간 FPS/메모리 검증 후 별도 배포 확인.

**필수 테스트:** 6방향 노출, 이미 결정된 광물 불변, 청크 경계·음수 좌표, 64m 해제 후 복원, 256m 초과 초기화, 저장 실패 롤백, 재접속·다중 탭, 기존 v1/v2/v3 저장, 상점 위치 무관 접근, 상하 무한 이동.

구현·테스트·배포·실기기 검증은 별개로 보고한다.
