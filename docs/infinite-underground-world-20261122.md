# DIG — 무한 지하 월드 설계 변경 (2026-11-22)

> 상태: **승인된 설계 방향 기록 / 게임 런타임 미구현**. 이전의 `docs/infinite-chunks-shop-protection-20261122.md`에 정의된 매점 건물·보호구역 및 수평 무한 월드 제안은 이 문서로 **대체**한다. 기존 `main` 배포·저장 데이터는 변경하지 않는다.

## 1. 월드와 시작 위치
- 하늘, 태양광, 지표면, 최상층/최하층 경계를 없앤 **X/Y/Z 3차원 무한 지하 월드**.
- 플레이어 키는 1m, 최소 블록 변 길이는 0.5m로 유지한다.
- 월드 원점 부근 청크 중앙에 안전하게 서 있을 수 있는 작은 시작 공동을 생성한다. 초기 생성 공간은 채굴 가능하되 플레이어가 지형 안에 끼이지 않도록 스폰 검증을 한다.
- 16m × 16m × 16m 청크는 **제안 기본값**이다(0.5m 복셀 기준 축당 32개). 음수 좌표를 포함해 청크 좌표는 floor 나눗셈을 사용한다.
- 월드 생성 시 암석·공동 등 기초 지형을 구성하고, 광물 종류는 아래 노출 이벤트에서 결정한다.
- 하늘빛 대신 램프·광물 발광·인공 조명을 사용한다. 높이는 절대 Y 좌표로 표시한다. 무한 월드에서 부동소수점 정밀도 문제를 피하기 위해 먼 이동 시 렌더 원점을 재설정하는 방안을 검증한다.

## 2. 매점 제거 및 메뉴
- 매점 건물, 매점 플랫폼, 보호 반경, 매점 채굴 금지 로직을 **새 무한 월드 모드에서 제거**한다.
- 판매/구매/강화는 상점 메뉴로 제공하고 위치·고도와 무관하게 접근 가능하게 한다. 제작 메뉴는 유지한다.
- 기존 자원·골드·강화·제작·전설 장비 진행 기록은 보존한다. 지상에서만 거래/제작할 수 있는 기존 제한은 **새 모드에서만** 해제한다.
- 기존 `src/shopProtection.ts`는 초기 검토용 유틸이며 새 모드의 최종 채굴 경로에 연결하지 않는다. 기존 모드와의 호환성을 위해 무조건 삭제하지 않는다.

## 3. 청크 로딩과 초기화
- 플레이어 주변의 가까운 청크만 메모리에 로딩·렌더링한다. 거리 판정은 **3차원 유클리드 거리** 기준으로 청크 경계의 최근접점까지 계산해 경계 깜빡임을 줄인다.
- **제안 거리 기준**: 0–32m 표시/상호작용, 32–64m 렌더링·메모리 해제, 64–256m 변경 기록 유지, 256m 초과 시 청크의 채굴 기록 및 노출 광물 기록 초기화. 경계에 히스테리시스를 두고 한 프레임당 처리량을 제한한다.
- 재방문 시 월드 시드로 기초 지형을 재생성한다. 초기화된 청크는 **새 생성 회차(epoch)** 를 부여해 광물 재추첨을 허용한다.
- 청크 초기화는 플레이어 이동으로 멀어질 때만 수행하며, 세션을 종료했다는 이유만으로 256m 범위 내 기록을 삭제하지 않는다.
- 메모리 해제와 영구 초기화는 별도 동작이다. 메모리 해제만 된 청크의 채굴·광물 기록은 보존한다.
- 기록 삭제는 저장 성공 후 확정한다. 저장 실패 시 이전 변경 기록을 보존한다. 재방문 직전에는 해당 청크의 초기화 epoch 및 변경 상태를 원자적으로 읽는다.
- 256m 초기화는 채굴 흔적을 영구 보존하지 않는 **게임 규칙**이다. 광물 무한 재획득에 따른 경제 밸런스는 별도 검증한다.

## 4. 광물: 사전 배치 대신 노출 시 결정
1. 청크 최초 생성 시 **모든 숨겨진 복셀의 광물 종류를 사전 추첨하지 않는다**. 기본 지층과 공동/고체 상태만 결정한다.
2. 채굴로 고체 복셀이 제거되면 새로 공기에 접한 인접 복셀(최대 6방향)을 탐색한다.
3. 처음 노출된 고체 복셀에만 깊이·지역별 광물 확률표를 적용하여 암석 또는 광물 종류를 결정한다.
4. 이미 결정된 복셀은 청크 메모리 해제, 재로드, 저장·복원 후에도 **동일 종류**를 유지한다. 카메라 시야에 들어왔다는 이유만으로 재추첨하지 않는다.
5. 청크 초기화가 확정되면 노출 광물 결정 기록도 삭제한다. 재방문 후 새 epoch에서 새 노출 이벤트가 일어나면 재추첨한다.
6. 청크 경계의 인접 복셀도 정확히 처리한다. 아직 로딩되지 않은 이웃 청크에는 노출 이벤트를 지연 기록하거나 동일한 결정 함수를 적용하여 누락/중복을 방지한다.
7. 확률 예시(미확정): 일반 암석 65%, 석탄 18%, 철 10%, 금 5%, 희귀 광물 2%. 지역/고도에 따라 달라질 수 있다.

**결정적 난수 키:** `worldSeed + chunkXYZ + localVoxelXYZ + chunkEpoch + lootTableVersion`. 광물 종류는 최초 노출 시 이 키로 결정하고 결과를 기록한다. 같은 epoch에서는 채굴 순서·프레임 속도·재접속에 따라 결과가 바뀌지 않는다. 새로운 epoch는 이전 epoch와 다른 결과를 낼 수 있다.

## 5. 채굴·저장·성능
- 채굴 시간은 기존 기준 대비 3배로 늘리되 도구/강화 효과는 유지한다. 채굴 버튼 누름 주기와 실제 파괴 타이머의 의미를 확인한 뒤 중복 배율을 방지한다.
- 저장: 기존 v1/v2/v3 데이터는 읽기 가능하게 유지하고 신규 무한 월드 저장을 **별도 네임스페이스/버전**으로 추가한다. 좌표·청크 epoch·제거된 복셀·노출 광물 결정을 관리한다.
- 이미 채굴된 광물 보상은 기존 재화·인벤토리 기록과 중복 지급되지 않게 처리한다. 초기화 후 새 광물 재획득은 허용하되 경제 테스트를 통과해야 한다.
- Three.js 청크 메시는 지연 생성하고, 멀어지면 geometry를 dispose 한다. 생성·삭제·노출 광물 결정은 프레임당 예산을 제한한다.
- 플레이어가 위아래로 이동해도 충돌, 조명, 이동, 카메라, UI, 채굴 범위가 정상 작동해야 한다.

## 6. 구현 순서와 검증
1. 신규 월드 모드와 저장 분리; 기존 4개 광산/저장 비파괴.
2. X/Y/Z 청크 생성·해제·초기화 및 음수 좌표/원점 이동 검증.
3. 시작 공동과 충돌·조명·무한 상하 이동 구현.
4. 매점 오브젝트 제거, 상점/제작/강화 메뉴로 전환.
5. 최초 노출 시 광물 결정·청크 경계 처리·epoch 기반 재생성 구현.
6. 채굴 시간 3배, 중복 보상/저장 충돌 방지.
7. Node/TypeScript/Chromium 회귀 테스트, 모바일 가로·세로·장시간 FPS/메모리 검증 후 별도 배포 확인.

**필수 테스트:** 6방향 노출, 이미 결정된 광물 불변, 청크 경계·음수 좌표, 64m 해제 후 복원, 256m 초과 초기화, 저장 실패 롤백, 재접속·다중 탭, 기존 v1/v2/v3 저장, 상점 위치 무관 접근, 상하 무한 이동.

구현·테스트·배포·실기기 검증은 별개로 보고한다.

## 7. 자동 전진·자동 채굴 및 모바일 최소 UI (2026-11-22 추가)
- 새 무한 지하 모드의 기본 행동은 **자동 전진 + 전방 자동 채굴**이다. 사용자는 이동 방향 조정과 메뉴 선택에 집중한다.
- 진행 상태 머신: `PAUSED → MOVING → MINING → MOVING`. 진행 방향에 고체 블록이 감지되면 충돌 전에 정지하고, 기존 대비 3배 채굴 타이머(도구/강화 보정 포함)를 진행한다. 파괴 및 보상 커밋이 끝난 후 자동 전진을 재개한다.
- 전방이 비어 있으면 계속 전진한다. 벽이 아닌 절벽·낙하 구간·미로딩 청크·저장 오류 등 위험 상황에서는 전진을 멈춘다. 지하 수직 이동은 방향 입력/별도 상승·하강 조작에 의해서만 수행하며 무조건 아래로 파고들지 않는다.
- 방향 입력: 모바일 가상 조이스틱 또는 화면 드래그(시점/진행 방향을 일관되게 정의); PC는 마우스와 방향키를 지원한다. 입력이 없으면 마지막 진행 방향을 유지한다.
- 기본 화면: 조작 영역, 자동 진행 상태, **일시정지/재개**, 아이콘 메뉴만 노출. 수동 DIG 버튼과 중복 텍스트 버튼은 기본 UI에서 제거한다.
- 아이콘 메뉴: **상점, 가방, 제작, 강화, 설정**. 아이콘에 접근성 이름/툴팁을 부여하고 모바일 터치 영역을 충분히 확보한다. 상세 화면에만 텍스트를 표시한다.
- 메뉴가 열리면 이동·채굴 타이머를 일시정지하고, 닫으면 사용자 설정에 따라 재개한다. 앱 비활성화/브라우저 탭 전환 시 자동 진행을 정지한다.
- 자동 채굴은 최초 노출 광물 결정 로직과 동일한 제거 커밋 경로를 사용한다. 청크 경계에서 중복 채굴·보상 지급을 방지한다.
- 기존 수동 조작 및 저장 데이터와의 호환성을 확인하고 새 모드에 단계적으로 적용한다.

**추가 테스트:** 전방 장애물 감지 후 정지/채굴/재출발, 빈 공간 이동, 낙하/미로딩 청크 안전 정지, 메뉴·탭 전환 시 일시정지, 방향 전환, 장시간 자동 채굴 성능, 중복 보상 방지, 모바일 아이콘 터치/접근성.

## 8. 권장 설계안 승인 및 기본 구현값 확정 (2026-11-22)
사용자 결정: **상세 설계의 권장 항목을 모두 기본 구현 사양으로 채택**한다. 본 문서의 '제안', '권장', '예시', '미확정' 표현은 아래 항목에 대해서는 기본값 확정으로 해석한다. 실제 구현·성능 테스트에서 문제를 발견한 경우에만 근거와 변경 이력을 기록하고 조정한다.

| 항목 | 확정 기본값 |
| --- | --- |
| 월드 | 하늘·지표면·상하 경계 없는 X/Y/Z 무한 지하 |
| 시작 | 원점 부근 청크 중앙의 안전한 작은 공동 |
| 캐릭터/복셀 | 키 1m / 최소 블록 0.5m |
| 청크 | 16×16×16m, 음수 좌표 floor 기반 |
| 로딩/초기화 | 0–32m 활성, 32–64m 렌더·메모리 해제, 64–256m 변경 기록 유지, 256m 초과 초기화 |
| 광물 | 최초 노출 시 결정, 같은 epoch에서 불변, 초기화 후 새 epoch |
| 기본 광물 확률 | 일반 암석 65%, 석탄 18%, 철 10%, 금 5%, 희귀 광물 2%; 깊이/지역별 표 확장은 후속 작업 |
| 채굴 | 기존 기준 시간 ×3, 도구·강화 보정 유지 |
| 이동 | 자동 전진, 전방 장애물에서 정지·자동 채굴·재전진 |
| 방향 조작 | 모바일 조이스틱/드래그, PC 마우스/방향키 |
| UI | 상점·가방·제작·강화·설정 아이콘 + 일시정지/재개 |
| 상점 | 매점 건물/보호구역 없음, 위치 무관 메뉴 접근 |
| 안전 | 절벽·미로딩 청크·저장 오류 정지, 메뉴·비활성 탭 일시정지 |
| 데이터 | 기존 저장 유지, 신규 모드 별도 네임스페이스/버전 |

위 값은 **설계상 확정**이며 현재 실행 중인 게임에 구현 완료되었다는 의미가 아니다. 충돌 안전성, 실제 FPS/메모리, 모바일 터치 조작을 검증하기 전에는 배포 완료로 표시하지 않는다.

## 9. 채굴 효율·랜덤 드롭 강화안 (2026-11-22, 신규 권장안)
**목표:** 자동 전진·자동 채굴의 성장 체감, 희귀 발견의 기대감, 장기 목표를 강화한다. 이 절은 신규 **권장안**으로서 8절의 기존 확정 사양을 덮어쓰지 않는다. 수치는 밸런스 테스트 전 임시값이다.

### 채굴 효율
- 장비 강화 시 기본 채굴 소요 시간을 단축한다. **3배로 늘어난 기본 채굴 시간**에 강화 배율을 적용하며 최저 채굴 시간을 둔다.
- 일정 강화 단계에서 인접 블록 추가 채굴 또는 범위 확대를 해금한다. 추가 파괴 블록은 일반 채굴과 동일한 광물 최초 노출·보상 커밋 경로를 사용한다.
- 연속 자동 채굴 시 효율 보너스를 부여하되 상한을 두고, 메뉴·안전 정지로 인한 일시정지는 불합리한 페널티를 주지 않는다.
- 초반에는 속도, 중반에는 범위, 후반에는 광물 보너스 등 서로 다른 성장 목표를 제공한다.

### 드롭과 희귀 발견
- 기존 블록의 **광물 종류 확률**(8절의 65/18/10/5/2)과, 채굴 완료 후 **추가 드롭 등급 확률**을 별도 표로 관리한다. 두 확률을 혼동하거나 중복 추첨하지 않는다.
- 추가 드롭 등급: 일반 / 고급 / 희귀 / 영웅 / 전설. 등급별 확률과 아이템 목록은 구현 전에 별도 테이블로 정의하고 UI에서 확인할 수 있게 한다.
- 무료 플레이 채굴에서만 랜덤 보너스를 제공한다. 현금·유료 재화로 구매하는 확률형 뽑기, 현금 교환, 반복 결제 유도는 도입하지 않는다.
- 희귀 드롭에는 짧은 시각·음향 효과, 수집 도감, 제작 목표를 연결한다. 연출은 끄거나 줄일 수 있게 한다.
- 연속 미획득 시 보장 보상(천장)을 제공할 수 있도록 카운터를 설계하고, 재접속·청크 초기화에도 악용되지 않도록 플레이어 단위로 저장한다.
- **중복 보상 방지:** 제거 성공한 복셀별 고유 채굴 이벤트에 대해서만 1회 드롭을 확정하고, 자동 채굴/범위 채굴/저장 재시도에서 재지급하지 않는다.
- 256m 청크 초기화 후 다시 채굴할 수 있는 규칙을 고려해 희귀 드롭 획득 속도 및 인플레이션을 시뮬레이션한다.

### 검증
- 장비 단계별 분당 채굴 블록 수, 광물·골드 획득량, 등급별 드롭 기대 횟수 및 실제 분포를 측정한다.
- 자동 채굴 1시간 연속 실행 시 FPS, 메모리, 저장 크기 및 보상 중복 여부를 검사한다.
- 광물 확률표와 추가 드롭 확률표를 각각 검증하고, 천장 카운터가 저장/복원·초기화에 영향받지 않는지 확인한다.

## 10. 채굴 장비 내구도·마모·수명 (2026-11-22 권장안)
**목표:** 강화된 채굴 속도·범위·보너스가 무한정 유지되지 않도록 장비별 내구도와 장기 수명을 부여한다. 아래 수치는 밸런스 검증 전 권장 기본값이다.

| 현재 내구도 비율 | 상태 | 실효 채굴 성능 배율 |
| --- | --- | --- |
| 71–100% | 정상 | 100% |
| 41–70% | 마모 | 90% |
| 11–40% | 심한 마모 | 70% |
| 1–10% | 고장 직전 | 50% |
| 0% | 고장 | 자동 채굴 중단 |

- 채굴 완료 시 블록 경도·도구 종류에 비례해 내구도를 소모한다. 채굴 실패·저장 재시도·중복 이벤트에는 소모하지 않는다.
- 강화 단계는 영구 기록으로 유지하되 강화로 얻은 속도·범위·효율 보너스를 **실효 성능 배율**로 감소시킨다. 실제 파괴 시간은 기존 3배 기본 시간, 강화 보정, 내구도 보정을 한 번씩 적용한다.
- 범위 채굴 시 추가 제거 블록에 따른 내구도 비용을 계산하고, 채굴·보상·내구도 변경을 단일 이벤트로 처리한다.
- 0% 도달 시 안전하게 자동 채굴을 중단한다. 메뉴형 상점에서 골드·광물로 수리하고, 설정에서 자동 수리 또는 예비 장비 자동 교체를 선택할 수 있다.
- 수리할 때마다 최대 내구도가 조금씩 감소한다. 최대 내구도가 하한에 도달하면 장비를 교체하거나 별도의 재제작 경로를 이용한다. 영구 강화 이력과 소모성 장비 인스턴스는 구분해 저장한다.
- 모바일 HUD는 장비 아이콘 아래 작은 내구도 막대만 표시하고, 임계치·고장 시에만 짧은 알림을 띄운다. 상세 수치와 수리 비용은 장비/상점 메뉴에 표시한다.
- 자동 수리는 사용자가 명시적으로 활성화해야 하며, 설정한 골드·재료 보유 하한 이하로는 자동 소비하지 않는다. 유료 확률형 수리/파손 복구는 도입하지 않는다.
- 기존 저장 데이터에는 내구도 필드가 없으므로 기존 장비는 최초 마이그레이션 시 **현재 최대 내구도 100%** 로 초기화하고, 기존 강화 단계·인벤토리는 보존한다.
- 내구도는 청크 초기화/재접속으로 복구되지 않으며 플레이어 장비 상태로 별도 저장한다.

**테스트:** 임계치 경계(70/40/10/0%), 강화 배율 적용, 범위 채굴 비용, 중복 채굴 이벤트, 저장 실패·재접속·다중 탭, 자동 수리 자원 하한, 최대 내구도 감소, 기존 저장 마이그레이션.

## 11. 장비 수명·자동 채굴 경제 상세 설계 (2026-11-22, 권장안)
### 11.1 장비 인스턴스와 영구 성장의 분리
- `equipmentInstanceId`를 장비 개체별 고유 ID로 두고 `equipmentType`, `baseMaxDurability`, `maxDurability`, `currentDurability`, `repairCount`, `condition`을 기록한다.
- 영구 성장(해금한 장비 설계도·계정 강화 연구·도감)은 장비 인스턴스와 분리한다. **개별 장비 강화 레벨은 장비 자체에 귀속**되며 새 장비로 무조건 복제되지 않는다. 장비 교체 시 성장 손실을 완화할 수 있도록 계정 연구 보너스와 재료 회수 시스템을 제공한다.
- 기본 내구도 1,000, 일반 암석 채굴 1, 경질 암석 2~5 소모를 **초기 밸런스 기준**으로 채택한다. 내구도는 정수로 관리한다.

### 11.2 마모와 수리
- 실효 성능 배율은 10절 기준(100/90/70/50/0%)을 적용한다. 채굴 이벤트 시작 시 도구의 현재 내구도를 확인하고, 제거 성공 시 마모를 원자적으로 반영한다.
- 수리는 현재 최대 내구도까지 복구하되 수리 1회당 **최초 최대 내구도의 1%** 만큼 최대 내구도가 감소한다. 최대 내구도 하한은 최초 최대의 **50%**다.
- 최대 내구도 하한에 도달한 장비는 일반 수리를 더 이상 제공하지 않고 교체/재제작을 유도한다. 다만 갑작스러운 진행 차단을 피하기 위해 저효율 기본 도구를 항상 제공한다.
- 수리 비용은 현재 내구도 손실량과 장비 등급에 비례하는 골드 + 광물로 산정한다. 비용 공식과 정확한 단가는 밸런스 테스트에서 결정하며 UI에 실행 전 표시한다.
- 자동 수리는 기본 **꺼짐**. 사용자가 설정한 최소 골드·재료 잔량을 침해하지 않는 경우에만 작동한다. 자동 수리 실패 시 채굴을 멈추고 아이콘 알림을 표시한다.

### 11.3 자동 채굴과 보상 트랜잭션
1. 이동 방향의 블록과 청크 로딩·충돌·낙하 위험을 검사한다.
2. 전방이 막혀 있으면 자동 정지 후 채굴 시간을 진행한다.
3. 채굴 성공 시 복셀 제거, 광물 보상, 추가 드롭, 장비 내구도 소모를 **하나의 채굴 이벤트 ID**에 묶는다.
4. 저장 성공 후 다음 전진을 허용한다. 저장 실패 시 보상 재지급·마모 중복을 방지하고 안전 정지한다.
5. 내구도 0이면 자동 수리(설정·자원 허용 시) 또는 예비 장비 교체를 시도한다. 불가능하면 정지하고 사용자에게 알린다.
6. 청크 256m 초기화는 장비 내구도·수리 횟수·보상 지급 이력을 되돌리지 않는다.

### 11.4 성장·보상 균형
- 분당 채굴 블록 수, 분당 순골드(판매 수익−수리 비용−제작 비용), 희귀 드롭 획득 시간, 장비 평균 수명을 핵심 지표로 측정한다.
- 강화할수록 채굴 효율은 증가하되 내구도 소모 및 교체 비용과 비교해 **실질 순수익이 성장**하도록 조정한다.
- 전설 장비는 채굴 효율·희귀 보상에 강점이 있지만 영구 무마모 장비는 만들지 않는다.
- 유료 확률형 수리·현금 교환은 도입하지 않는다. 추가 드롭 확률과 보장 규칙은 명확히 공개한다.

### 11.5 구현·검증 조건
- 저장 버전 확장 시 기존 장비를 현재/최대 내구도 100%로 이행하고 강화·재화 기록을 유지한다.
- 자동 채굴 중 메뉴 열기, 앱 백그라운드 전환, 청크 경계 이동, 다중 탭, 저장 실패에 대한 상태 전이를 검증한다.
- 1/2/5 내구도 차감, 71/70/41/40/11/10/1/0% 경계, 50회 이상 수리 후 최대 내구도 하한, 장비 교체, 자동 수리 자원 하한, 1시간 자동 채굴 경제 시뮬레이션을 테스트한다.
- **상태: 상세 설계 권장안, 코드·테스트·배포 미완료.**

## 12. 광물 분포 규칙 변경 — 고도·깊이 무관 전역 랜덤 (2026-11-22, 최신 확정)
**사용자 최신 결정:** 상하 무한 청크이므로 광물 종류 및 출현 확률을 Y좌표, 깊이, 고도, 지층 단계, 지역에 따라 구분하지 않는다. 본 절은 4절의 '깊이·지역별 확률', 8절의 '깊이/지역별 표 확장'과 충돌하는 내용을 **대체**한다.

- 채굴로 새로 노출되는 각 고체 블록은 전역 공통 확률표로 종류를 최초 1회 결정한다.
- 공통 확률(기본값): 일반 암석 65%, 석탄 18%, 철 10%, 금 5%, 희귀 광물 2%. 모든 X/Y/Z 위치에 동일하게 적용한다.
- 결정적 난수 키는 `worldSeed + chunkXYZ + localVoxelXYZ + chunkEpoch + lootTableVersion`을 유지한다. 좌표는 난수의 고유 입력일 뿐 **광물 가중치/등급을 바꾸는 조건이 아니다**.
- 광물 분포는 모든 방향에서 통계적으로 동일하며, 더 높거나 깊게 이동해도 희귀 광물 확률이 증가하거나 감소하지 않는다.
- 광물 종류 결정과 채굴 완료 후 추가 드롭 등급 추첨은 서로 다른 시스템으로 유지한다. 추가 드롭에도 고도·깊이 보정을 넣지 않는다.
- 광물 최초 노출 결정, 청크 경계 처리, 256m 초과 청크 초기화 및 새 epoch 재추첨 규칙은 유지한다.
- 장비 성능·내구도·블록 경도는 광물별로 달라질 수 있으나 **출현 확률은 위치와 무관**하다.
- 테스트: Y=-10000/0/+10000 및 서로 다른 X/Z에서 같은 표 적용, 통계적 분포, 재접속 후 광물 불변, epoch 변경 후 새 추첨, 추가 드롭과 광물 확률 분리.
- **상태:** 설계 문서 확정. 런타임 코드 변경·테스트·배포는 별도 작업.

## 13. 전역 광물 확률·추가 드롭·자동 채굴 효율의 분리 (2026-11-22, 후속 상세 권장안)
### 13.1 확률 계층
- **1차: 블록 광물 종류** — 12절 확정값(일반 암석 65%, 석탄 18%, 철 10%, 금 5%, 희귀 광물 2%)을 모든 X/Y/Z에서 동일하게 적용한다. 장비·강화·고도·청크 위치는 1차 확률에 영향을 주지 않는다.
- **2차: 채굴 성공 시 추가 드롭** — 채굴 완료 이벤트에서 별도 추첨한다. 장비 보너스는 2차 드롭 수량·확률에만 적용 가능하며 1차 광물 확률을 바꾸지 않는다.
- **3차: 보장 보상** — 추가 드롭 미획득 횟수에 따른 천장 카운터는 플레이어 단위로 저장한다. 청크 초기화로 초기화되지 않는다.
- 최초 노출 시 1차 광물 결정과 채굴 완료 시 2차 추가 드롭 추첨은 서로 다른 시점에 실행한다. 노출만으로 인벤토리에 보상을 지급하지 않는다.

### 13.2 추가 드롭 확률 권장 초기안
추가 드롭 이벤트 발생 확률은 채굴 성공 블록당 **10%**로 시작한다. 발생한 경우 등급을 다음 비율로 추첨한다. 미발생 90%는 추가 아이템 없음이다.

| 추가 드롭 발생 시 등급 | 조건부 확률 | 전체 채굴당 확률 |
| --- | ---: | ---: |
| 일반 | 60% | 6% |
| 고급 | 25% | 2.5% |
| 희귀 | 10% | 1% |
| 영웅 | 4% | 0.4% |
| 전설 | 1% | 0.1% |

- **권장 천장:** 추가 드롭 기준 연속 500회 전설 미획득 시 다음 추가 드롭을 전설로 보장한다. 카운터는 '추가 드롭 발생 횟수'로만 증가하며, 일반 채굴 500회와 혼동하지 않는다. 발동 시 0으로 초기화한다.
- 장비의 추가 드롭 보너스는 이벤트 발생 확률을 높이는 방식으로 시작하되 **최대 20%**로 제한한다. 발생 시 등급 조건부 확률은 유지한다.
- 모든 확률과 보장 조건을 게임 내 정보 메뉴에서 공개한다. 유료 확률형 구매 및 현금 교환은 적용하지 않는다.

### 13.3 효율·내구도·경제
- 분당 블록 제거 수 = 자동 채굴 성공 횟수 + 범위 채굴로 추가 제거된 블록 수. 범위 채굴로 제거된 각 블록은 독립 보상·내구도 비용을 가지되 한 번만 정산한다.
- 내구도는 광물 종류의 경도와 실제 제거 블록 수로 차감한다. 이동만으로 소모되지 않는다.
- 장비 강화는 1차 광물 분포를 바꾸지 않고, 채굴 시간/범위 및 2차 드롭 발생 확률을 개선한다.
- 채굴 완료 이벤트 ID에 복셀 제거·광물 보상·추가 드롭·천장 카운터·내구도 차감을 함께 기록하여 재접속·저장 재시도 중 중복 정산을 방지한다.
- 256m 원거리 청크 초기화 후 재채굴은 허용하지만 플레이어 장비 수명·천장 카운터·이미 받은 보상은 유지한다.

### 13.4 검증 기준
- 최소 100만 회 모의 채굴로 1차 분포와 2차 드롭 분포를 각각 검증하고, 고도 -10000/0/+10000에서 같은 확률표가 적용되는지 확인한다.
- 천장 499→500→보장 및 자연 전설 획득 시 카운터 초기화, 드롭 확률 10→20% 상한, 범위 채굴 중복 지급, 저장 실패·다중 탭, 청크 epoch 초기화 이후 장비·천장 보존을 테스트한다.
- 수치는 **밸런스 검증 전 권장 초기안**이며 12절의 전역 광물 확률은 사용자 확정값으로 유지한다.
- **상태:** 설계 작성, 게임 코드·자동 테스트·배포 미완료.

## 14. 강화 단계별 자동 채굴 효율 수치 (2026-11-22, 후속 권장안)
### 14.1 강화 단계 표
| 강화 | 기본 채굴 시간 단축 | 1회 성공 시 최대 제거 블록 | 추가 드롭 발생 확률 |
| --- | ---: | ---: | ---: |
| +0 | 0% | 1 | 10% |
| +1 | 8% | 1 | 11% |
| +2 | 16% | 1 | 12% |
| +3 | 24% | 2 | 14% |
| +4 | 32% | 2 | 17% |
| +5 | 40% | 3 | 20% |

- 위 표는 **초기 밸런스 권장안**이며 장비 강화 성공률/보호석 설계와 별개다.
- 광물 1차 등장 확률은 모든 강화 단계와 X/Y/Z 위치에서 **65/18/10/5/2% 고정**. 추가 드롭은 13절의 2차 추첨만 변경한다.
- 실제 채굴 시간은 `기존 기본 채굴 시간 × 3 × (1 - 강화 시간 단축률) ÷ 내구도 성능 배율`로 계산한다. 단, 내구도 0%에서는 채굴 불가. 도구별 별도 속도 보정이 있으면 중복 적용되지 않도록 공통 계산 경로에서 처리한다.
- +3/+4의 2블록, +5의 3블록은 **최대 제거 개수**다. 첫 대상 복셀을 포함하며 인접 고체 블록이 없으면 적게 제거한다.
- 범위 채굴 대상은 전방 기준 인접 복셀 중 고정된 탐색 순서로 선택한다. 벽 너머 임의 원거리 블록, 미로딩 청크, 플레이어 발밑 위험 지형을 자동 파괴하지 않는다.
- 각 실제 제거 복셀은 광물 보상·추가 드롭·내구도 차감을 개별 정산하되, 단일 채굴 액션 ID로 원자적 저장 및 중복 지급 방지를 적용한다.
- 범위 채굴은 한 번의 채굴 타이머로 여러 블록을 제거할 수 있지만 내구도는 실제 제거 블록 수와 경도에 비례해 소모한다.
- 내구도 성능 배율이 감소하면 속도와 범위 보너스가 실효적으로 줄어들도록 한다. **범위 개수 계산 권장식:** `max(1, floor(1 + (강화 최대 제거 개수 - 1) × 내구도 성능 배율))`. 정상 100%일 때 표의 최대치를 제공한다.
- 연속 채굴 보너스가 추가되더라도 실제 시간·드롭 발생 확률의 상한(20%)을 넘지 않도록 검증한다.

### 14.2 검증
- +0~+5 각 단계별 시간, 최대 블록 개수, 2차 드롭 발생률을 자동 테스트한다.
- 내구도 100/90/70/50/0% 상태별 실효 속도·범위 및 고장 중단을 검증한다.
- 인접 청크 경계·음수 좌표·미로딩 청크·낙하 위험·저장 실패에서 범위 채굴이 안전하게 작동하는지 확인한다.
- 최소 100만 건의 확률 모의 테스트로 **1차 광물 확률 불변** 및 2차 드롭 상한을 확인한다.
- 상태: 설계 권장안, 런타임 코드·테스트·배포 미완료.

## 15. 강화 성공률·실패·보호석·수리 비용 통합 설계 (2026-11-22, 후속 권장안)
### 15.1 강화 규칙
| 강화 시도 | 성공 확률 | 실패 결과 | 보호석 사용 |
| --- | ---: | --- | --- |
| +0 → +1 | 100% | 없음 | 불필요 |
| +1 → +2 | 85% | 강화 재료 소모, 단계 유지 | 선택(효과 없음) |
| +2 → +3 | 70% | 강화 재료 소모, 단계 유지 | 선택(효과 없음) |
| +3 → +4 | 55% | 강화 재료 소모, 단계 1 하락 | 하락 방지 |
| +4 → +5 | 40% | 강화 재료 소모, 단계 1 하락 | 하락 방지 |

- **강화 시도 비용**은 성공/실패 모두 소비하며, 골드 + 해당 등급 광물을 사용한다. 실제 수량은 경제 시뮬레이션으로 결정한다.
- 보호석은 하락 위험이 있는 +3→+4, +4→+5 시도에서만 소모하도록 한다. 성공 여부와 관계없이 보호석 1개를 소비하며 실패 시 강화 단계 하락만 방지한다. 보호석은 성공률을 올리지 않는다.
- 강화 실패는 장비를 파괴하지 않고 **현재 내구도·최대 내구도·수리 횟수를 바꾸지 않는다**.
- 강화 성공 시에도 현재/최대 내구도를 자동 복구하지 않는다. 수리와 강화는 별도 행동이다.
- 강화 등급은 장비 인스턴스에 귀속한다. 계정 영구 연구/해금과 구분하며 장비 교체 시 강화가 무조건 이전되지는 않는다.
- 무료 플레이로 강화 재료·보호석을 획득할 수 있어야 하며, 유료 확률형 강화/현금 교환은 도입하지 않는다.

### 15.2 수리 비용 산식 (초기 권장)
- 손상 비율 `damageRatio = (maxDurability - currentDurability) / maxDurability`.
- 장비 등급별 기본 수리 비용을 `baseRepairGold[equipmentTier]`로 두고, `repairGold = ceil(baseRepairGold[equipmentTier] × damageRatio × (1 + 0.25 × enhancementLevel))`로 계산한다.
- 광물 소모는 `ceil(baseRepairOre[equipmentTier] × damageRatio)`이며, 손상 0일 때 수리 불가·비용 0.
- 수리 완료 후 최대 내구도는 최초 최대의 1%만큼 감소(최저 50% 하한), 현재 내구도는 **감소한 새 최대 내구도**로 회복한다.
- 최대 내구도가 50% 하한에 도달한 장비는 **그 수리까지 허용**하고 이후 일반 수리를 중단한다. 기본 저효율 도구는 항상 사용 가능하게 유지한다.
- 수리 실행 전 예상 비용, 수리 후 최대 내구도, 남은 수리 가능 횟수를 UI에 표시한다.
- 자동 수리는 기본 꺼짐. 설정한 최소 골드·광물 보유량 이하로 자원을 소비하지 않으며 비용 부족 시 정지·알림한다.

### 15.3 거래 안전·테스트
- 강화와 수리는 각각 고유 거래 ID로 재료 소비, 장비 상태 변경, 저장을 원자적으로 처리한다. 실패·재접속·다중 탭에서 중복 소모 및 중복 성공을 막는다.
- 확률 추첨은 시도당 1회만 실행하고 결과를 저장한다. 저장 재시도로 성공 여부를 다시 추첨하지 않는다.
- +0~+5 경계, 보호석 유무, 실패 단계 하락, 강화/수리 동시 요청, 내구도 0, 수리 50% 하한, 자원 부족, 저장 실패를 자동 검증한다.
- 장기 경제 시뮬레이션에서 강화에 필요한 평균 채굴 시간과 수리 비용 대비 순수익을 측정한다.
- **상태:** 설계 권장안. 코드 구현·테스트·배포 미완료.

## 16. 장비 제작·판매·채굴 순환 경제 (2026-11-22, 후속 권장안)

### 16.2 장비 제작 초기 비용표
| 장비 등급 | 제작 골드 | 필요 광물 | 기본 수리 골드 계수 | 기본 수리 광물 계수 |

- 제작비·재료 수량은 **초기 시뮬레이션용 권장값**이며 플레이 테스트 후 조정한다.
- 제작 장비는 새로운 장비 인스턴스로 생성하고 최초 최대 내구도 1,000 및 현재 내구도 100%로 시작한다. 계정 영구 연구는 유지하되 이전 장비 개별 강화 레벨은 자동 이전되지 않는다.
- 기본 도구는 수리·교체 비용 없이 항상 제공하되 제작 장비보다 낮은 효율을 갖는다. 이를 통해 재화 부족 시에도 게임 진행이 막히지 않도록 한다.
- 15절의 수리 산식에서 `baseRepairGold[equipmentTier]`와 `baseRepairOre[equipmentTier]`는 위 표를 참조한다. 수리 광물은 해당 장비의 대표 광물을 사용한다.
- 수리 후 최대 내구도 감소와 50% 수명 하한, 자동 수리 보호 재고 규칙은 11·15절을 따른다.

### 16.3 자동 판매·제작·수리 우선순위
1. 자동 채굴로 광물/추가 보상을 지급하고 장비 내구도를 차감한다.
2. 자동 판매가 켜져 있으면 **재료 보호 재고량**을 제외한 초과 광물만 판매한다.
3. 장비 내구도 임계치 도달 시 사용자가 허용한 자동 수리를 검토한다. 골드·재료 보호 하한을 침해하면 실행하지 않는다.
4. 수리 불가능한 장비는 예비 장비로 교체한다. 없으면 기본 도구로 전환해 진행 가능성을 유지한다.
5. 제작·강화는 기본적으로 사용자 메뉴 확인을 요구한다. 자동 제작·자동 강화는 기본 비활성화한다.
6. 판매·제작·수리·강화 거래는 각각 고유 거래 ID로 중복 지급/소모를 방지한다.

### 16.4 밸런스 검증 지표
- `분당 총수익 = 분당 실제 제거 블록 수 × 5.62골드 + 추가 드롭 판매 수익` (전량 판매 가정, 추가 드롭 미포함 시 해당 항목 0).
- `분당 순수익 = 실제 판매 수익 − 수리 비용 − 제작/교체 비용의 시간당 환산 − 강화 비용의 시간당 환산`.
- +0~+5 강화와 기본/철/금/희귀 장비 조합별로 **블록/분, 골드/분, 수리 주기, 평균 교체 시간, 희귀 보상/시간**을 비교한다.
- 채굴 범위가 넓어져도 추가 제거 블록마다 내구도와 보상 처리가 정확히 발생해야 한다.
- 256m 청크 초기화 후 광물 재추첨은 허용하되, 장비 마모·재화·도감·보장 카운터는 초기화하지 않는다.
- 최소 1시간/10시간 모의 채굴에서 상위 장비가 순수익·진행 속도 면에서 의미 있는 개선을 주는지 검증하고, 경제가 무한히 팽창하지 않도록 수리·교체 소모를 조정한다.
- **상태:** 상세 설계 권장안, 코드 구현·테스트·배포 미완료.

## 17. 채굴 효율·장비 수명·경제 시뮬레이션 상세 설계 (2026-11-22, 권장안)
### 17.1 시뮬레이션 목적과 범위
- 1시간·10시간·100시간 자동 채굴을 모의 실행해 강화 +0~+5 및 기본/철/금/희귀 장비의 **제거 블록 수, 광물별 획득량, 판매 총수익, 추가 드롭, 내구도 소모, 수리 횟수, 교체 횟수, 순수익**을 비교한다.
- 월드 X/Y/Z 좌표와 깊이·고도에 관계없이 12절의 전역 광물 확률(암석 65%, 석탄 18%, 철 10%, 금 5%, 희귀 2%)을 동일하게 적용한다.
- 13절의 추가 드롭과 천장, 14절의 강화별 채굴 속도·범위·추가 드롭 확률, 15절의 강화·수리, 16절의 판매가·제작비를 분리된 입력으로 사용한다.
- **설계 단계에서는 측정 결과를 만들어 내지 않는다.** 시뮬레이터 실행 후에만 실제 수치·통과 여부를 보고한다.

### 17.2 입력 변수와 산식
- `baseMineSeconds`: 기존 게임 기본 채굴 시간(코드에서 실측/확인). 새 기준 시간은 `3 × baseMineSeconds`. 임의의 초 단위 값을 확정하지 않는다.
- `enhancementSpeedReduction`: +0~+5에 대해 0/0.08/0.16/0.24/0.32/0.40.
- `durabilityPerformanceMultiplier`: 현재 내구도 비율에 따라 1/0.9/0.7/0.5/0.
- `effectiveMineSeconds = 3 × baseMineSeconds × (1 - enhancementSpeedReduction) / durabilityPerformanceMultiplier`. 0% 내구도는 채굴 중단/교체 경로로 처리한다.
- `maxBlocksPerAction`: +0~+5에 대해 1/1/1/2/2/3. 실제 범위 블록 수는 인접 유효 블록과 내구도 상태로 제한한다.
- `expectedBaseOreSaleGoldPerBlock = 5.62`: 16절 판매가와 전역 확률의 가중합. **전량 판매·추가 드롭 제외** 기대값.
- `grossGold = 실제 판매한 광물 매출 + 실제 판매한 추가 드롭 매출`; `netGold = grossGold - 수리 지출 - 제작/교체 지출 - 강화 지출`. 제작에 사용한 광물은 판매 매출에 포함하지 않으며, 광물의 기회비용은 별도 지표로 집계한다.
- `durabilitySpent = Σ(실제 제거된 각 블록의 경도별 내구도 비용)`. 1회 범위 채굴에서 3블록을 제거하면 3블록의 비용을 모두 더한다.
- `durabilityPerMinute = durabilitySpent / elapsedMinutes`; `repairIntervalMinutes`는 수리 임계치와 실제 마모량으로 계산하며 고정 시간으로 가정하지 않는다.
- 수리 시 최초 최대 내구도 1% 감소, 하한 50% 도달 이후 수리 불가 규칙과 재료·골드 보호 재고를 적용한다.

### 17.3 실행 매트릭스
- 장비 4종 × 강화 6단계 × 시간 3종(1/10/100시간) = **72개 기본 시나리오**.
- 각 시나리오에 고정 시드 최소 100개를 사용하여 평균·중앙값·하위 10%·상위 10%를 보고한다. 72 × 100 = **7,200회 실행**.
- 정상/마모/심한 마모/고장 직전 상태, 자동 수리 켬/끔, 자동 판매 켬/끔, 예비 장비 유무, 수리 재료 부족을 별도 경계 시나리오로 테스트한다.
- 블록 경도별 실제 비용과 범위 채굴의 인접 블록 유효율은 게임 코드 확인 또는 명시적 실험 입력으로 공급한다. 입력이 미정이면 결과를 확정 수치로 발표하지 않는다.
- 성능 평가에서는 16m 청크, 32/64/256m 거리 단계, 음수 좌표, Y=-10000/0/+10000, 256m 청크 재생성, 저장 재접속을 포함한다.

### 17.4 자동 검증 기준
1. 전역 광물 종류 확률이 고도·깊이·장비 강화에 따라 달라지지 않아야 한다.
2. 추가 드롭은 1차 광물과 별도로 추첨하고 장비 보너스 상한 20%를 지켜야 한다.
3. 채굴 성공 1블록당 광물 보상과 내구도 소모가 정확히 1회 반영되어야 한다.
4. 범위 채굴로 제거한 블록마다 보상·마모를 각각 반영하고 저장 재시도 시 중복 반영하지 않아야 한다.
5. 수리 횟수 증가에 따른 최대 내구도 감소와 50% 수명 하한을 지켜야 한다.
6. 상위 강화/장비의 **시간당 순수익**이 하위 장비보다 개선되는지 비교한다. 역전 시 자동으로 밸런스 경고를 생성하되 무조건 통과로 간주하지 않는다.
7. 채굴·수리·강화·제작 비용으로 재화가 음수가 되지 않아야 하며, 보호 재고 하한을 침범하지 않아야 한다.
8. 256m 청크 초기화·앱 재시작·다중 탭 이후에도 장비 수명·보장 카운터·거래 ID는 유지되어야 한다.

### 17.5 결과 보고 형식

- 보고서에는 입력 버전, 월드 시드 목록, 계산 공식, 가정, 검증 실패 목록, 권장 조정값을 기록한다.

## 20. 원거리 청크 초기화의 세계관: 지반 붕괴 (2026-11-22)
- **확정 스토리:** 끝없는 지하 세계의 암반은 채굴로 지지력을 잃는다. 플레이어가 충분히 멀어지면 버려진 갱도는 지반 압력으로 붕괴해 다시 암석으로 메워진다.
- 기존 청크 거리 정책 유지: 0~32m 활성, 32~64m 언로드, 64~256m 채굴 상태 임시 보존, **256m 초과 시 '붕괴'로 청크 수정·발견 상태 초기화** 및 generation epoch 증가.
- 붕괴는 플레이어 시야 밖에서만 확정하고, 화면 안에서 갑자기 벽이 생기거나 캐릭터가 매몰되는 현상을 금지한다. 경계 진동 방지를 위한 거리 히스테리시스 적용.
- 재방문 시 새 epoch 기반으로 아직 드러나지 않은 암석 종류를 다시 결정한다. 모든 X/Y/Z 좌표의 광물 출현 확률은 동일하며 깊이·높이별 차등을 두지 않는다.
- 붕괴는 **세계 지형만 초기화**한다. 플레이어 인벤토리, 골드, 장비 내구도·강화, 연구, 보너스 드롭 천장 카운터, 완료된 보상 거래 기록은 초기화하지 않는다.
- 게임 안내 문구 예시: '멀리 떠난 갱도는 지반 압력으로 붕괴합니다. 다시 돌아오면 새로운 암석을 채굴할 수 있습니다.'
- 구현 시 붕괴 직전 미저장 보상·거래를 먼저 안전하게 확정하고, 저장 실패 시 초기화를 연기한다. 재방문 광물 재추첨은 블록 제거 보상 중복 지급을 허용하지 않는다.
- **상태:** 스토리·설계 확정, 실제 원거리 청크 붕괴 연출과 초기화 코드는 미구현.


## 21. 무중력 지하 세계 설정 (2026-11-22)
- **확정 세계관:** 정체불명의 중력 소실 현상으로 지하 세계 전역이 무중력 상태다. 하늘·지표·최하층은 존재하지 않으며 상하좌우 어느 방향으로든 동일한 지하 공간이 계속된다.
- 캐릭터는 중력 낙하·착지·낙하 피해 없이 3차원 6방향 이동 가능. 기존 지상 기준 점프/낙하 판정은 새 세계 모드에서 비활성화.
- 자동 전진/채굴은 카메라의 3차원 바라보는 방향(상하 pitch 포함)을 따라 이동하며, 전방 암석 발견 시 정지·채굴 후 재개한다. 사용자 조작은 방향 전환과 아이콘 메뉴 중심.
- 채굴 보상은 무중력 공간에 드롭 오브젝트로 방치하지 않고 즉시 인벤토리에 지급. 기존 원자적 보상·저장 규칙 유지.
- **붕괴 설정과 정합성:** 먼 갱도는 중력 때문에 무너지는 것이 아니라, 불안정한 암반의 내부 응력·압력과 균열 전파로 붕괴한다. 시야 밖 256m 초과 청크 재생성 규칙 유지.
- '낙하 위험 시 자동 이동 정지' 조건은 무중력 모드에서 제거. 대신 미생성 청크 진입, 저장 실패, 메뉴, 포커스 이탈, 충돌 및 매몰 위험을 정지 조건으로 사용.
- 신규 무중력 모드는 기존 저장/지상 모드와 분리하고, 구형 세이브 호환성을 유지한다.
- **상태:** 스토리·게임 규칙 확정. 기존 `src/main.ts`의 중력 가속도·지면 충돌·수평 이동은 아직 구형 구현이며 무중력 3D 이동으로 교체되지 않았다.
