# DIG 4D 시공간 포탈 구현 상세설계

2026-11-25 · 무작위 포탈 생성, 소형/대형 통과 규칙, 물리 통과와 청크 생명주기

## 1. 목적과 적용 범위

포탈은 채굴 청크를 다른 공간과 시간대에 연결하는 실제 물리 통로다. 입구의 흡인, 먼지·광물의 유입, 출구에서의 방출을 장식 애니메이션이 아닌 중력·속도·충돌로 구현한다. 이 문서는 포탈 생성부터 한 방향 통과, 열차 전량 통과 후 출발 청크 초기화까지 정의한다.

시작 튜토리얼 청크에는 입구 하나를 보장한다. 이후 청크는 소형·대형 여부를 독립 무작위 판정하여 포탈 없음, 한 종류만 존재, 두 종류 동시 존재를 모두 허용한다. 확률 수치는 밸런스 설정값이며 과거 프로토타입의 소형 10%·대형 3%는 확정값으로 간주하지 않는다.

## 2. 포탈 생성 계약

### 2.1 생성 절차

1. 청크 생성 요청에 `tutorialStart` 또는 `ordinary` 역할을 포함한다.
2. `tutorialStart`이면 무작위 판정을 건너뛰고 정확히 하나의 대형 입구를 만든다. 입구가 가려진 암반 표면 뒤에 위치하도록 둔다. 이 입구의 출구 쌍은 다른 청크/시간대로 연결한다.
3. 일반 청크는 `small`과 `large` 존재를 별개의 난수 샘플로 판정한다. 서로 독립이므로 없음/소형만/대형만/둘 다의 결과가 가능하다.
4. 존재 판정된 종류별로 해당 크기의 포탈 쌍 ID와 현재 청크의 한 끝을 만든다. 다른 끝은 별도 위치·시간 프로필을 가진다. 쌍의 두 끝을 같은 화면 안에 나란히 만들지 않는다.
5. 포탈 면은 실제 통과 가능한 암반 경계에 맞춰 배치한다. 충돌구조와 메쉬 aperture의 위치·크기·방향을 같은 변환값에서 계산한다.
6. 포탈 속성은 해당 청크 세션 동안 고정한다. 청크가 초기화된 뒤 새로 생성될 때만 새 판정을 한다. 재접속 시 월드가 새로 생성되므로 이전 연결과 위치는 이어지지 않는다.

일반 청크에서는 종류별로 최초 구현 기준 포탈 끝을 최대 하나씩 배치한다. 소형과 대형 판정이 모두 성공하면 두 종류가 동시에 존재할 수 있다. 나중에 한 종류의 다중 생성이 필요하면 개수 확률을 별도 규칙으로 추가한다.

### 2.2 무작위 독립성

`rollSmall(random)`과 `rollLarge(random)`은 독립 샘플을 받는다. 같은 난수 샘플을 재사용하거나 한 종류가 성공하면 다른 종류를 배제하지 않는다. 난수원은 주입 가능해야 하고, 청크 생성에서 확정한 결과는 `SessionChunks`에 한 번만 저장한다. 렌더 재생성·화면 회전·청크 재조회는 다시 굴리지 않는다.

과거 10%/3% 값은 코드 프로토타입 기준 기록일 뿐이다. 새 설정은 `portalBalance` 값으로 외부화하며 최종 확률을 확정하기 전까지 임의로 배포 밸런스에 고정하지 않는다. 시작 청크 보장 입구는 이 확률과 무관하다.

### 2.3 방향과 시간 정보

- 각 포탈 쌍은 고유한 `pairId`, 크기, 입구/출구 역할, 통과 방향, 숨겨진 목적지 청크 ID, 시대 프로필을 갖는다.
- 포탈 축은 청크의 유효 암반면 중 무작위로 선택한다. 여섯 주축 방향을 같은 가중치로 뽑은 뒤 실제 설치 가능한 면을 고른다. 중력 방향과 통과 축은 포탈 면의 법선에 맞춘다.
- 입구/출구 쌍의 이동은 한 방향만 허용한다. 입구 반대 방향에서 역으로 들어가거나 출구 방향에서 되돌아가려 하면 aperture 충돌면에 막힌다.
- 시간대 연결 정보는 목적지의 숨은 시대 프로필로 저장한다. 지역 청크는 필요할 때 lazy 생성한다. 플레이어 UI에는 목적지 좌표·연도·시간차를 표시하지 않는다.
- 포탈 너머 장면은 몇 초마다 다른 장소/시대의 시각 잔상으로 바뀐다. 이 미리보기는 실제 연결을 바꾸지 않는다. 선두 기계가 입구 통과를 시작할 때 현재 연결 ID를 통과 세션에 고정하고, 열차 꼬리가 완전히 나온 뒤까지 연결을 변경하지 않는다.

## 3. 통과 크기와 허용 물체

| 대상 | 소형 통로 | 대형 통로 |
| --- | --- | --- |
| 먼지 | 중력에 끌려 입구로 유입, 출구에서 계속 방출 | 동일 |
| 광물·작은 발견품 | 통과 가능 | 통과 가능 |
| 소형 거래 드론 | 통과 가능 | 통과 가능 |
| 플레이어 기계 | 통과 불가. 흡인되어도 입구 면에서 충돌/미끄러짐 | 통과 가능 |
| 열차 및 화물차 | 통과 불가 | 연결된 consist 단위로 통과 |
| 대형 장비·화물 | 규격 초과 시 막힘 | 통과 가능 여부를 실제 aperture 크기와 충돌체로 판정 |

통로 입구의 중력장은 크기와 무관하게 주변 먼지·광물·아이템을 끌어당긴다. 대형 통로에서는 플레이어와 열차도 중력에 이끌린다. 소형 통로는 플레이어를 끌어당길 수 있어도 통과 허용 목록과 aperture 충돌 규칙이 우선하여 기계가 빠져나가지 못한다.

## 4. 물리장과 먼지/물품 이동

기존 `portalGravityAcceleration()`은 입구에서 안쪽, 출구에서 바깥쪽 방향과 거리 감쇠를 제공한다. 통합 단계에서는 단일 기계 위치뿐 아니라 물리 대상마다 같은 포탈 필드를 질량/크기 정책에 따라 적용한다.

- 중력 가속도는 위치에 따라 연속적으로 변하고 영향 반경 경계에서 0으로 부드럽게 줄어든다. 포탈 밖의 일반 영역에는 통로 중력이 없다.
- 먼지·광물은 입구 쪽으로 실제 이동하고 aperture 면 통과 시 짝 출구에서 방출된다. 시각 파티클만 빨려 들어가고 아이템 데이터가 사라지는 처리는 허용하지 않는다.
- 출구 먼지는 항상 작은 유량으로 바깥에 흐른다. 광물/아이템은 낮은 확률의 방출 이벤트로 생성된다. 이벤트 확률은 채굴 보상 확률보다 낮게 두며 정확한 수치는 조정 가능한 설정이다.
- 방출 물체는 출구 법선 방향 속도를 받고 중력·관성·충돌을 따른다. 주변 지형이나 플레이어/열차와 충돌해 튕기거나 쌓일 수 있고, 회수는 기존 자동 수집/인벤토리 규칙으로 한 번만 처리한다.
- 소형 출구에서는 통과 크기 제한에 맞는 광물·소형 물품만 나온다. 대형 장비는 대형 출구만 통과한다.
- 출구 방출 이벤트에는 `pairId + transit/session sequence` 기반 중복 방지 키를 둔다. 프레임 재시도나 세이브 복원으로 동일 물품을 중복 생성하지 않는다.

## 5. 포탈 감지와 사용자 안내

- 포탈이 포함된 청크가 로드되고 플레이어가 센서 범위에 들어오면 센서 UI에 방향/위치 단서를 표시한다. 목적지 식별자나 시대 정보는 감추고, 거리·중력 변화에 따라 같은 표시만 갱신한다.
- 시작 청크에서는 첫 자동 전진이 시작되는 순간 보장 입구 방향을 안내한다. 포탈 앞을 막은 광석이 남아 있으면 센서는 신호를 알려도 강한 흡인/통과는 활성화하지 않는다.
- 접근할수록 먼지 유속·방향성이 점진적으로 강해진다. 물리장 신호와 먼지 효과는 동일한 상대 위치 및 필드 강도를 사용한다.
- 입구를 막던 마지막 광석이 제거되면 aperture와 중력장이 활성화된다. 채굴 전부터 중력으로 벽을 통과해 끌려가는 현상은 없도록 한다.
- 시야를 포탈 반대쪽으로 돌리면 자동 전진 방향도 바뀐다. 정지 버튼은 자동추진을 끄고 유한한 역추력 제동을 요청한다. 중력은 계속 계산되며, 제동/회피가 추력 한계를 넘으면 물리적으로 즉시 멈추지 않는다.

## 6. 포탈 통과 및 열차 생명주기

### 6.1 이동 세션

- 통과는 기계/아이템이 입구의 물리 경계를 넘는 동안 `TransitSession`을 만든다. 세션은 `pairId`, 연결 목적지/시대 snapshot, 진입 프레임, 통과 대상 ID 목록을 고정한다.
- 물체는 입구에서 중력으로 가속되고, 좁은 내부 통로를 지나 출구에서 같은 상대 운동 방향을 보존해 나온다. 내부 통로 표현은 시야/사운드 연출로 감출 수 있지만 결과는 실제 이동 시간과 충돌에 연결한다. 입력 한 번으로 좌표를 순간 변경하는 구현은 하지 않는다.
- 소형 통과 세션은 통과 대상마다 처리하고 열차 청크 전환을 발생시키지 않는다. 대형 통과 세션은 선두 기계와 결합 열차를 한 consist로 취급한다.
- 열차는 연결 순서 및 차량 ID를 유지한다. 각 차체가 포탈 면을 차례로 통과하고 출구 쪽에 놓이는지 확인한다. 크기/충돌 때문에 진입할 수 없는 차량은 억지로 이동시키지 않고 입구 앞에 남아 안전 정지/탈출 선택이 가능해야 한다.

### 6.2 출발 청크 초기화

1. 선두가 통과를 시작해도 출발 청크는 즉시 제거하지 않는다.
2. 연결 열차의 마지막 차량이 출구 쪽에서 온전히 생성되고 물리 충돌 준비가 끝날 때까지 출발·중간 청크를 유지한다.
3. 전체 consist 통과 완료를 확인한 뒤 이전 청크의 지형·광물·바닥 물품·포탈 연결 기록을 초기화한다.
4. 영구 열차/장비/인벤토리/연구/도감 저장은 청크 초기화와 분리한다. 청크 안에서 회수하지 않은 물품은 사라진다.
5. 청크 한 변 16m를 넘는 열차 길이는 위험 경고 대상이다. 경계에 남은 후미 차량·화물은 세계 재설정 규칙으로 소실될 수 있다. 정상 길이 안에서 전량 통과한 차량은 청크 삭제만으로 손실되지 않는다.

통과/초기화 이벤트는 `pairId + consistId + transitId`로 멱등 처리한다. 중복 이벤트는 저장 데이터나 물리 객체를 두 번 이동시키지 않는다.

## 7. 초기 타입/모듈 제안

```ts
export type PassageSize = 'small' | 'large';
export type PassageEnd = 'inlet' | 'outlet';

export type PassageEndpoint = Readonly<{
  endpointId: string;
  pairId: string;
  size: PassageSize;
  end: PassageEnd;
  chunkId: string;
  center: readonly [number, number, number];
  normalIntoPassage: readonly [number, number, number];
}>;

export type PassagePair = Readonly<{
  pairId: string;
  size: PassageSize;
  inlet: PassageEndpoint;
  outlet: PassageEndpoint;
  destinationEraId: string;
}>;
```

- `portalGeneration.ts`: 역할별 시작 청크 override, 독립 크기 판정, 방향/면 선택, pair ID 생성.
- `passageRegistry.ts`: 세션 내 endpoint와 pair 연결, lazy 목적지 청크 생성, 중복 생성 방지.
- `portalGravity.ts`: 기존 필드 계산 재사용. 물체별 적용/입출구 관성 변환을 별도 순수 함수로 분리.
- `passageTransit.ts`: aperture 방향 진입·허용 크기·이동 세션·출구 배치 단계를 관리한다.
- `trainTransit.ts`: consist의 차량별 통과 순서와 꼬리 통과 완료를 추적한다.
- `chunkResetPolicy.ts`: transit 완료 신호 후 source chunk 상태/렌더링/세션 기록 제거.
- `passageDust.ts`, `passageDrops.ts`: 저비용 먼지 이동과 드문 출구 물품 생성. 물리 결과 및 중복 키를 저장한다.

## 8. 검증 시나리오와 완료 기준

- 시작 청크는 난수 결과와 무관하게 입구 하나만 가진다. 첫 통로를 제외한 일반 생성에서는 소형/대형 독립 판정의 네 결과가 모두 가능하다.
- 같은 청크를 여러 번 로드해도 포탈과 목적지 페어가 재추첨되지 않는다. 청크 초기화 후 재생성할 때만 새 판정이 발생한다.
- 소형 통로에서 광물과 소형 드론은 지나가고, 기계·열차·대형 장비는 충돌면을 통과하지 않는다.
- 대형 통로에서 기계와 차량이 순서대로 물리 이동하고 상대 속도가 보존된다. 역방향 입구/출구 통과는 막힌다.
- 먼지는 입구로 이동하고 출구에서 상시 유출된다. 무작위 출구 물품은 채굴보다 낮은 빈도로 한 번만 지급된다.
- 앞을 가린 광석 제거 전에는 흡인력/통과가 꺼져 있고, 제거 뒤만 켜진다. 정지/회피는 유한 추력·중력·속도를 반영한다.
- consist 꼬리가 출구로 나오기 전 source chunk가 삭제되지 않는다. 전체 통과 뒤에는 임시 월드만 삭제되고 영구 열차 저장은 유지된다.
- 청크를 넘어 생기는 시각 오류, 중복 회수, 열차 ID 분실, 청크 삭제 중 dangling mesh가 없다.
- 저사양 모드에서도 근접 기계·열차는 고정 시간 간격 물리, 멀리 있는 먼지는 묶음 업데이트로 제한한다.

| 소형·대형 출현 확률 | 독립 판정은 확정, 실제 확률은 미정 설정값. 과거 10%/3%는 프로토타입 참고값 |
| 일반 청크의 종류별 개수 | 첫 구현은 청크당 크기별 최대 한 끝; 소형+대형 동시 존재 가능 |
| 입구 방향 | 여섯 주축 중 유효 면을 동일 가중치로 선택 |
| 중력 반경·세기·마찰 | 설정값으로 분리, 질량/속도 영향과 모바일 가속 상한 적용 |
| 포탈 내부 통과시간 | 연출/물리 파라미터. 물체 크기와 이동 속도를 반영하며 순간 이동 금지 |
| 출구 물품 확률/간격·종류 | 채굴 기본 보상보다 낮게 설정, 정확한 값은 밸런스 검증 전까지 조정 가능 |
| 세계 시간대 차이 범위 | 쌍의 시대 프로필은 저장하되 플레이어에게 숫자/연도는 노출하지 않음 |

본 설계는 세계관/물리 연결의 초기 구현 계약이다. 수치가 미정인 값은 상수로 코드 곳곳에 박지 말고 조정 설정에 모은다.
