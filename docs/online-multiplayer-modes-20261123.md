# DIG 온라인 모드 설계 (2026-11-23)

상태: 설계안. 서버, 매칭, 전투, 동기화는 아직 미구현. 기존 싱글플레이와 `?world=infinite-preview` 저장 데이터는 그대로 보존한다.

## 공통 구조
- 진입: 메인 메뉴 → 온라인 → 협력 / 수집 대결 / 약탈 → 방 생성·코드 참가·빠른 매칭.
- 기본 2~4인 방. 향후 서버 성능 측정 후 확장. 플레이어는 사람 아바타가 아니라 구체형 채굴 잠수함이며, 드릴·열차형 저장고·엔진 등급이 보인다.
- 서버 권위(authoritative): 월드 시드, 광물 노출 시 판정, 채굴 시간, 내구도, 적재량, 이동속도, 제작·강화 비용, 점수, 피해·탈취 및 분배는 서버에서만 확정한다. 클라이언트는 입력과 렌더링 담당.
- 네트워크: 인증된 세션 + WebSocket, 방별 tick과 위치/행동 상태 델타 전송. 청크는 시드 기반 생성 후 변경 이벤트만 전송. 재접속은 서버 스냅샷과 이벤트 순번으로 복구.
- 계정·닉네임·차단·신고·방장 추방·비공개 방, 접속 종료 및 잠수 처리. 익명 공개 매칭에는 속도 제한과 악용 방지.
- 모든 재화 변화는 서버 트랜잭션 ID로 멱등 처리. 로컬 저장 파일을 온라인 재화로 직접 업로드하거나 인정하지 않는다.
- 모바일 조작: 방 목록, 팀원 상태, 적재율, 전투 경고와 분배 기록을 간결하게 표시.

## A. 협력 / 균등분배
- 팀 공유 채굴 진행, 광물 획득량은 방의 공동 장부에 먼저 적립.
- 종료 또는 정산 시 **각 광물 종류별**로 인원수에 따라 균등 분배. 예: 철 10개/3명 → 3개씩, 나머지 1개는 다음 정산으로 이월. 임의로 한 명에게 몰아주지 않는다.
- 입장/퇴장 시 정산 구간을 닫아 참가자별 기여 시점을 고정. 중도 이탈·재접속 악용 방지.
- 개인 드릴 내구도, 엔진, 화물칸은 각자 소유. 협력 채굴에 소비되는 개인 장비 내구도는 공동 분배와 별도로 기록.
- 저장고 가득 찬 참가자는 받을 몫을 서버의 수령 대기함에 보관하고, 저장고 여유가 생기면 수령. 버려지거나 타인에게 재분배되지 않는다.
- 방 설정에서 팀 공유 업그레이드는 선택 사항이며, 참여자 사전 동의가 필요하다.

## B. 수집량 대결
- 동일 시드, 동일 초기 드릴/엔진/저장고 사양의 독립 채굴 구역 또는 동등 조건의 대칭 구역에서 시작.
- 기본 10분 라운드(방 설정으로 조정). 점수는 서버가 확인한 **실제 채굴·수집 완료량** 기준. 기본 1광물=1점, 종류별 가중 점수는 별도 규칙 방에서만 적용.
- 제작에 사용한 광물도 누적 수집 점수에는 남고, 현재 보유량과 별도 집계. 중복 채굴/수집 이벤트는 무효.
- 실시간 순위, 종료 결과, 동점 공동 순위. 서버 시간 기준 시작/종료. 접속 끊김 시 타이머는 계속 진행.
- 대결방에서는 약탈·타인 방해 불가. 방 생성 시 공개된 규칙은 라운드 도중 변경 불가.

## C. 약탈 (명시적 동의 PvP)
- 약탈 전용 방에서만 활성화. 일반 협력방·대결방·싱글 모드에서는 타 플레이어 공격 불가.
- 플레이어의 구체형 잠수함과 화물 열차를 공격 대상으로 하며, 무기와 방어 장비는 드릴 내구도와 구분.
- 기본 보호: 입장 후 30초, 리스폰 후 15초 무적; 안전 구역에서는 공격·약탈 불가. 무적 중 본인도 공격 불가.
- 전투 승리 시 **방 안에서 수집한 비보호 광물**의 최대 20%만 탈취. 최소 잔여량 보호(예: 종류별 5개), 인벤토리 용량을 초과하는 약탈은 불가.
- 이미 사용한 재료, 설치된 저장고, 엔진, 장착 드릴, 개인 싱글 저장 데이터는 탈취 불가.
- 전투 결과는 서버에서 원자적으로 정산: 피해·방어·승패·탈취량·수용량 검증 후 소유권을 단일 트랜잭션으로 이전. 재전송·동시 약탈·접속 종료 중복 지급 방지.
- 반복 표적 괴롭힘 방지: 동일 대상 연속 약탈 쿨다운, 패배 후 임시 보호, 방 나가기 허용. 실제 화폐 구매 재화는 약탈 대상에서 제외.

## 서버 데이터 개요
- Room(id, mode, rulesVersion, seed, status, startedAt, endsAt)
- Membership(roomId, playerId, joinedAt, leftAt, role, session)
- PlayerState(position, orientation, health, drill, cargo, engine, inventory, invVersion)
- WorldChunkEdit(roomId, chunkKey, voxelIndex, mineral, eventSeq)
- MiningEvent(eventId, playerId, voxel, startTick, completeTick, mineral)
- CooperativeLedger(roomId, settlementId, mineral, total, perPlayer, remainder)
- MatchScore(roomId, playerId, minedCount, score)
- CombatEvent(eventId, attacker, defender, damage, protection, lootTransfer)
- Snapshot(roomId, tick, eventSeq, stateHash)

## 구현 단계와 완료 기준
1. **P0 프로토콜/규칙:** 모드별 상태기계, 룸 생성/입장/종료, 광물별 점수·균등분배·약탈 상한 순수 함수와 자동 테스트.
2. **P1 협력 MVP:** 2인 WebSocket 동기화, 채굴 서버 검증, 공동 장부, 원자적 균등 정산, 중도 이탈/재접속 테스트.
3. **P2 대결 MVP:** 동일 시작 조건, 서버 타이머, 중복 이벤트 방지, 실시간 점수판, 종료 정산.
4. **P3 약탈 MVP:** 명시적 PvP 방, 안전 구역, 전투, 보호 시간, 20% 상한, 서버 트랜잭션과 악용 회귀 테스트.
5. **P4 안정화:** 모바일 4인 실기기, 지연/패킷 손실/재접속/동시 정산/치트 방어 부하 시험, 모니터링과 배포 롤백.

## 보안 및 운영 결정 필요
- 호스팅 및 운영비, 계정 인증 방식, 지역별 서버, 개인정보 보존 정책, 신고 처리 절차.
- 공개 PvP와 사설 방의 매칭 정책 및 어린이 사용자 보호.
- 온라인 보상은 별도 경제로 시작하고, 싱글/온라인 재화 이동은 검증된 이전 규칙이 생기기 전까지 금지.
