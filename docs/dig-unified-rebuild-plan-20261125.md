# DIG 기존판 보존과 통합설계판 구축 계획

2026-11-25 기준. 이 문서는 전환을 구현할 때 사용할 주소, 빌드, 저장, 게임 진행, 공개 판정 기준을 정의한다. 아래의 보존 경로와 시험 경로는 예정 주소다.

## 1. 기준점과 주소

현재 Pages는 클래식과 4D 시제품을 하나의 Vite 빌드로 제공한다. 보존 기준은 두 게임이 함께 배포된 커밋 [9bdccd9](https://github.com/jflakeee/dig/tree/9bdccd99ee8c96a2f19ab782a9064e892be7d30e)이다. 구현 착수 시 이 커밋을 태그로 고정하고 배포물, 자산 목록 및 체크섬을 함께 보관한다. [현재 빌드 설정](../vite.config.ts) · [Pages 워크플로](../.github/workflows/build.yml)

| 주소 | 병행 개발 중 | 신판 정식 공개 후 |
| --- | --- | --- |
| `/dig/` | 기존 클래식 | 통합설계판 |
| `/dig/dig-4d.html` | 보존판 검증 후 기존 북마크를 보존 4D로 연결 | 같은 연결 유지 |
| `/dig/versions/2026-11-25/` | 고정된 클래식 | 같은 버전 계속 제공 |
| `/dig/versions/2026-11-25/dig-4d.html` | 고정된 4D 시제품 | 같은 버전 계속 제공 |
| `/dig/next/` | 신판 시험 공개 | 루트의 정식판으로 연결 |

기존 4D 주소는 쿼리와 프래그먼트를 유지해 보존판으로 이동시킨다. README에서 현재 정식판, 시험판, 보존판을 구분한다. 이전 작업 브랜치의 실험은 해당 커밋으로 추적한다.

## 2. 빌드와 배포물 조립

1. 기준 커밋을 별도 디렉터리에 체크아웃해 Vite의 base를 `/dig/versions/2026-11-25/`로 지정한다. 두 HTML, JS, 스타일과 자산을 함께 보관한다. 기준 트리에 npm 잠금 파일이 없어 나중에 재빌드하면 의존성이 달라질 수 있다. 최초 검증한 산출물과 체크섬을 고정하고 이후 배포 때 같은 파일을 사용한다.
2. 신판은 전용 HTML과 TypeScript 진입점에서 부팅한다. 좌표 계산, 충돌, 저장 검증 등 기존 모듈은 통합설계와 동작이 일치하는 범위에서 재사용한다. 병행 개발 중 신판의 base는 `/dig/next/`다.
3. 각 빌드를 독립 출력 폴더에서 완료한 뒤 클래식 루트, 보존판, 시험판을 하나의 Pages 배포물로 조립한다. 공개 직전 각 HTML이 참조하는 자산 경로와 응답 형식을 확인한다. Pages 배포는 한 번에 하나씩 진행한다.
4. 정식 전환 때 같은 신판 릴리스를 루트 base인 `/dig/`로 빌드한다. 보존판 두 주소는 계속 배포물에 포함한다.

## 3. 저장과 복원 호환

| 실행판 | 저장 계약 | 플레이어 동작 |
| --- | --- | --- |
| 기존 클래식 | 기존 키 `dig-p0-v1` 유지 | 같은 브라우저에서 보존 주소를 열면 기존 광산을 이어간다. |
| 기존 4D | 기존 키 `dig-4d-train-v1`과 DIG4R1 공유 코드 유지 | 보존판에서 기존 열차 기록을 재개하거나 클립보드 코드로 복원한다. |
| 통합설계판 | 별도 키 `dig-unified-v1` 제안. 시험판과 승격한 정식판이 같은 키와 스키마를 사용 | 첫 진입은 새 인트로로 시작한다. 초기화는 이 판의 진행만 지운다. |

같은 출처의 경로들은 브라우저 저장 공간을 공유한다. 판별 키와 쓰기 잠금 이름을 버전별로 관리한다. 기존 코드를 신판에 가져올 때는 형식·체크섬·지원 필드를 검사하고 변환 미리보기를 보여준다. 장비·광물·연구 ID의 대응이 정의된 버전만 가져올 수 있다. 미지원 코드는 보존판 복원 주소를 안내한다. 새 데이터 형식의 공유 코드는 자체 버전을 사용한다. 적용 직전 현재 진행을 클립보드로 백업하며, 취소·충돌 시 기존 상태를 보존한다. 신판의 저장 형식이 시험 기간에 변경되면 승격 전에 이전 시험 저장의 변환 또는 복구를 확인한다.

## 4. 구현 순서와 완료 기준

| 단계 | 구현 범위 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- |
| 0. 보존판 | 기준 배포물 고정, 두 보존 주소와 기존 북마크 연결 | 저장이 있는 브라우저에서 두 게임이 각각 기존 기록을 읽고, 복원·초기화가 대상 게임에만 적용된다. |
| 1. 첫 플레이 | 여섯 방향이 암반으로 막힌 공간, 순차 점등과 레이저음, 일반 암석 카운트. 3개에서 제작 버튼을 열고 한 번 차감해 첫 드릴을 장착한다. 채굴 중 체인을 고정하고 몸체가 통과할 폭이 확보되면 회수·전진한다. | 새 저장으로 휴대폰에서 화면 방향과 표시된 버튼만 사용해 진행한다. 자동 작업 중 정지, 정지 후 안전한 경우 재개가 나타난다. |
| 2. 첫 포탈까지 연결 | 시작 청크에 대형 입구 하나를 보장한다. 첫 전진에서 센서가 방향을 알리고 먼지가 빨라진다. 가림 암반 제거 후 흡인이 시작된다. | 정지·방향 전환으로 탈출하는 경로와 그대로 통과하는 경로를 모두 완주한다. 통과 시 영구 진행을 보존한다. 이 단계가 첫 시험판 범위다. |
| 3. 반복 탐험 | 16m 청크·시야, 최초 노출 시 블록 판정, 독립적인 포탈·미세중력 생성, 출구 방출, 여러 화물칸과 먼 청크 붕괴 | 마지막 차량의 포탈 통과 전에 출발 청크가 유지된다. 16m 초과 편성은 먼 청크에 남은 차량·화물만 소실 대상이 된다. |
| 4. 성장과 거래 | 드릴 손상·수리·추가 제작, 긴급 레이저, 세라믹, 에너지, 연구·조감도, 드론 매매·경매, 간헐적 기억 대사 | 고장과 재료 부족에서 채굴로 복구한다. 발견 기록은 청크 붕괴 후 유지된다. 경매 유찰·최대 10배 낙찰·낙찰 수수료가 한 번씩 정산된다. |

출현 확률, 수리 비용, 경매 수수료율 등 미정 수치는 시험 설정으로 기록한다. 첫 시험판은 [인트로](dig-4d-intro-implementation-detail-20261125.md)와 [포탈](dig-4d-portal-implementation-detail-20261125.md), 후속 기능은 [통합설계](DIG_unified_design.md)와 [최신 결정](PROJECT_MEMORY.md)을 기준으로 구현한다.

첫 시험판의 저장값별 재접속, 운행 버튼, 센서·흡인 판정은 [인트로 상세설계 3–6절](dig-4d-intro-implementation-detail-20261125.md)을 적용한다.

## 5. 공개 판정과 롤백

- 기존 재시작 검사에서는 초기 데이터를 넣는 스크립트가 페이지를 다시 열 때도 실행된다. 초기 데이터를 최초 한 번만 주입한 뒤, 재시작 시 이전 진행이 사라지는지와 다른 판의 저장이 유지되는지 확인한다. 수동 클립보드 복원과 다중 탭 충돌도 별도로 확인한다. [기존 검사](../tests/dig-4d-restore-smoke.ts)
- 시험 공개는 0–2단계, 정식 루트 전환은 3–4단계까지 완료한 릴리스를 대상으로 한다. 실제 iOS Safari와 Android에서 첫 포탈까지 플레이하고, 회전·백그라운드 복귀·저장 후 재접속을 확인한다. 빌드 성공, 주소별 로드, 저장 검증, 기기 검증 결과를 릴리스 기록에 남긴다.
- 전환 직전 배포물과 체크섬을 보관한다. 루트 또는 저장 검증 실패 시 직전 배포물을 다시 게시해 클래식 루트와 보존 주소를 복구한다. 신판 저장은 전용 키에 두어 수정판에서 계속 사용할 수 있게 한다.
