- **열차 도식:** 카메라가 전방만 보므로 3D 열차 대신 화면 왼쪽 아래에 도식을 둔다. 구체형 기체(큰 원)와 구체형 화물칸(작은 원)을 나란히 그리고, 칸마다 적재량을 아래부터 채워 보여준다. 16 m 밖 칸은 주황 테두리다.

**칸별 통과 진행 표시 (2026-11-27 추가):**
- 화물칸을 단 채 청크 경계를 넘으면, 열차 도식이 칸마다 경계 통과 상태를 보여 준다.
  - 통과: 초록 테두리
  - 대기: 흐리게
  - 소실(16 m 밖): 점선으로 흐리게
- 기체 앞이 경계를 넘은 뒤 달린 거리가 칸의 뒤끝(기체 2 m + 칸당 3 m)에 이르면 그 칸을 통과로 본다.
- 도식 옆에 `경계 통과 n/N`을 표시하고, 마지막 칸이 지나고 1초 뒤에 지운다.
- 넘친 광물의 회수는 튕겨낸 조각의 재수집으로 구현했다(용량 행 참고).
- 화물칸 개수 제한은 없다(장비 강화 설계 1절).

## 1. 범위와 확정 원칙

열차는 구체형 채굴 기계와 뒤에 연결되는 차량으로 구성한다. 플레이어는 화물칸을 추가할 수 있으며, 청크 한 변인 16m 이내가 안전한 전체 열차 길이다. 대형 포탈은 플레이어 기계와 열차를 한 방향으로 통과시킨다. 출발 청크는 열차 전체가 빠져나간 뒤 붕괴·초기화된다.

이 설계는 4D 모드 기준이다. 실험 프리뷰의 40개/칸, 최대 8칸, 엔진 5단계는 4D 확정값으로 가져오지 않는다.

## 2. 편성 및 길이 계산

편성은 플레이어 기계/견인부와 연결 차량의 순서가 있는 목록이다. 길이는 열차 앞끝부터 마지막 차량 뒤끝까지의 실제 연결 길이로 계산하며 차량 몸체와 연결부를 포함한다.

- 열차 총 길이 ≤16m: 안전 범위. 모든 차량과 화물은 청크 전환 과정에서 보존된다.
- 열차 총 길이 >16m: 경고 범위. 열차가 여러 청크에 걸치거나 후미가 먼 청크에 남은 상태에서 그 청크가 거리 조건으로 붕괴하면, 붕괴 청크 안의 차량과 적재물이 소실될 수 있다. 소실 위험은 차량 추가 및 출발 전에 명시한다.
- 차량 추가는 열차 길이·화물 공간·제작 재료를 모두 검사한다. 초과 편성도 의도적으로 허용할 수 있으나 위험 고지 후 플레이어가 직접 확정해야 한다.
- 길이 판정은 청크 내부 좌표축 투영만 쓰지 않고 연결된 차량의 물리적 길이를 합산한다. 통로 방향 전환으로 차량 길이를 짧게 계산하지 않는다.

차량별 길이·화물 용량·제작 재료는 설정값이며 아직 수치를 확정하지 않는다.

## 3. 차량과 화물 보존

각 차량은 고유 ID, 종류, 연결 순서, 손상/상태, 화물 목록을 가진다. 화물은 플레이어 임시 수집물과 구분해 차량별로 저장한다.

- 차량 분리/연결은 정지 상태에서만 가능하다. 연결을 확정하기 전에 새 총 길이와 초과 위험을 보여 준다.
- 화물칸의 적재 한도는 해당 차량의 용량을 따른다. 수량 단위와 적재 감속은 추후 밸런스 설정으로 둔다.
- 채굴 보상은 빈 공간이 있으면 우선 플레이어의 기본 수집 공간에 들어가고, 공간이 부족하면 선택된 화물칸에 적재한다. 어느 곳에도 공간이 없으면 자동 폐기하지 않고 청크 바닥에 드롭한다.
- 전체 열차 길이가 청크 길이(16m)를 초과한 상태에서 열차 후미가 멀어진 청크에 남고 해당 청크가 붕괴하면, 그 청크 안에 있던 차량과 차량 내부 화물이 함께 소실될 수 있다. 청크 바닥 드롭도 영구 인벤토리 보존 대상이 아니다.
- 열차 진행 저장에는 안전 길이 안의 차량과 화물을 포함한다. 청크 위치·광물 배치·바닥 드롭은 열차 세이브에 포함하지 않는다.

기본 수집 공간과 화물칸 간 자동 배분/우선순위는 UI 설계에서 설정한다. 안전 범위 내 차량과 화물은 포탈 이동 후에도 유지한다.

## 4. 실제 이동과 포탈 통과

열차는 물리적으로 견인·연결되어 움직이며 포탈 좌표 순간이동으로 각 차량을 개별 재배치하지 않는다.

1. 대형 입구에 접근하면 포탈 중력이 플레이어 기계와 연결 열차에 작용한다.
2. 포탈은 입구에서 출구로 한 방향만 허용한다. 소형 포탈은 열차 차량을 통과시키지 않는다.
3. 플레이어 기계가 출구로 나온 뒤에도 열차가 입구와 출구 사이에 남아 있는 동안 편성 전체와 전환 상태를 유지한다.
4. 마지막 차량의 뒤끝까지 출구를 완전히 벗어나면 전환을 완료한다. 그때 출발 청크 환경을 초기화하고 새 도착 청크 상태만 활성화한다.
5. 전환 도중 정지/장애/저장 오류가 발생하면 청크를 지우지 않고 안전 정지 상태를 저장한다. 이어서 이동을 재개하거나 마지막 안전 상태에서 복구한다.

먼지와 느슨한 광물은 포탈 중력에 따라 움직일 수 있다. 차량 커플링이 끊어지거나 포탈에서 튕겨나는 조건은 별도 물리 검증 대상이다.

## 5. 청크 초기화와 초과 길이 위험

청크 초기화는 출발 청크의 지형·광물·바닥 물품·포탈과 해당 청크에만 속한 임시 기록에만 적용한다. 영구 도감, 플레이어 장비, 열차 진행 세이브는 환경 기록과 분리한다.

열차 전체 길이가 16m를 넘으면 앞쪽 기계가 이동한 뒤에도 후미 차량이 멀어진 청크에 남을 수 있다. 그 청크가 거리 조건에 따라 붕괴할 때 청크 안에 남아 있던 차량과 화물은 소실될 수 있다. 이는 별도 확률 판정이 아니라 청크 붕괴에 포함되는 위험이다. 총 길이가 16m 이하인 편성은 이 초과 길이 소실 규칙의 대상이 아니다. 정확한 거리 조건과 청크별 차량 추적은 구현 시 스트리밍과 함께 검증한다.

청크 초기화 전에 다음 순서를 보장한다.

- 모든 차량의 마지막 위치와 화물 스냅샷 저장
- 열차 전체 통과 여부 확인
- 청크별 임시 상태와 영구 진행 저장소 분리
- 출발 청크 임시 상태 삭제
- 도착 청크에서 플레이어·열차 상태 복구

이 순서 중 저장이 실패하면 초기화를 중단하고 출발 청크를 보존한다.

## 6. UI 흐름

- 편성 화면에 차량 순서, 종류, 길이, 화물칸 사용량, 총 열차 길이/16m를 표시한다.
- 안전 범위에서는 추가 차량 버튼을 정상 표시한다. 초과 위험이면 길이 초과 경고를 보여주고 사용자가 명시적으로 확인해야 연결한다.
- 포탈 접근 중에는 “열차 전량 통과 전 출발 구역이 유지됨”을 표시한다. 자동 채굴/전진 정지 버튼은 계속 접근 가능해야 한다.
- 포탈 통과 중에는 “N대 통과 완료 / 총 M대”와 마지막 차량 통과 상태를 표시한다. 청크 초기화는 마지막 차량 통과 이벤트 이후에만 시작한다.
- 초과 길이 편성으로 진입할 경우 위험 고지와 예상 소실 대상(후미 차량/화물)을 가능하면 사전에 표시한다.
- 전환 완료 후 요약 메시지에 유지된 편성과 소실된 항목이 있으면 구분해 기록한다.

## 7. 저장·정산 원자성

차량 연결/분리, 화물 이동, 채굴 적재, 포탈 전환, 청크 초기화는 revision과 idempotency key를 사용하는 이벤트로 기록한다.

- 한 이벤트의 재시도는 차량/화물을 중복 생성하거나 중복 삭제하지 않는다.
- 포탈 전환 중에는 열차 편성에 대한 동시 편집과 거래/수리 작업을 잠근다.
- 열차 전체 통과를 확인하기 전에는 이전 청크의 내용이나 화물을 삭제하지 않는다.
- 저장 장애가 있으면 청크 삭제보다 정지·복구 가능성을 우선한다.
- 공유 복원 코드는 플레이어 진행에 포함된 열차와 화물을 복원할 수 있지만, 청크의 임시 바닥 드롭/위치는 복원하지 않는다. 미정산 거래는 별도 거래 규칙을 따른다.

## 8. 미정 설정과 완료 기준

미정: 차량별 길이와 화물 용량, 기본 수집 공간, 편성 상한, 적재 감속, 커플링 강도, 포탈 통과 시간/속도, 스트리밍 추적 여유 거리, 초과 편성의 구체 소실 조건.

완료 기준:

- 총 열차 길이는 기계와 모든 연결 차량을 포함해 16m 기준과 비교한다.
- 소형 포탈은 화물차/열차를 막고 대형 포탈만 편성 전체를 통과시킨다.
- 마지막 차량이 출구를 완전히 벗어나기 전에는 출발 청크가 초기화되지 않는다.
- 안전 길이의 열차·화물은 포탈 후 보존되고, 초과 편성은 사전 경고와 구체적 소실 위험을 가진다.
- 초기화는 청크 임시 기록에만 적용하고 영구 장비·도감·안전 편성 세이브를 지우지 않는다.
- 저장 실패·중복 입력에서도 차량/화물의 일부 복제, 무단 삭제, 보상 중복이 없다.
