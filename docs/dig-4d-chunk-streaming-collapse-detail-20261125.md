# DIG 4D 무한 청크 생성·시야 로딩·붕괴 상세설계

**2026-11-26 변경.** 시작·일반 청크의 포탈 생성 시점, 여섯 이웃 동시 생성, 개구 크기 및 지형 유형은 [면 채굴·지연 포탈·청크 형태 설계](dig-chunk-faces-and-portals.md)를 우선한다. 기존 첫 전진 즉시 탐지는 이전 시험판 동작이다.


2026-11-25 · 16m 무한 청크의 생성, 시야 범위 로딩, 먼 청크 초기화와 진행 데이터 분리

## 1. 기본 공간 규격

- 월드는 X/Y/Z 방향으로 이어지는 무한 지하이며 한 청크는 16m 정육면체다.
- 복셀 한 변은 0.5m, 청크당 32×32×32 복셀을 사용한다.
- 부분 메시 갱신 구역은 4m(8×8×8 복셀) 단위로 나눈다.
- 플레이어의 최대 시야는 16m다. 먼지 안개는 그 거리 안에서 점차 짙어지며 청크 경계를 넘어 먼 곳을 보이지 않게 한다.
- 16m는 시야·안전 편성 기준이지 월드의 끝이 아니다. 청크는 접근에 따라 계속 생성된다.

## 2. 청크 생성과 지연 생성

청크는 플레이어 주변에 필요한 시점에 생성하며 전 월드를 미리 만들지 않는다.

1. 플레이어가 인접 청크에 접근하면 청크 환경 골격과 암반 복셀을 생성한다.
2. 그 청크의 안정된 좌표와 epoch로 중력·포탈 등 청크 단위 환경 속성을 한 번 판정한다.
3. 광물/아이템 결과는 청크 생성 시 미리 배정하지 않는다. 암반이 채굴되어 새 블록이 처음 드러날 때 발견 생성 규칙을 호출한다.
4. 청크가 계속 유지되는 동안 같은 epoch의 환경 판정과 이미 드러난 블록 결과를 보존한다.
5. 청크 붕괴 후 같은 좌표가 새 epoch로 생성되면 환경 판정은 다시 하고, 새 암반의 광물 결과는 각 블록이 처음 드러날 때 다시 판정한다.

청크 생성, 통로 판정, 미세중력 판정, 블록 발견 판정은 별도 난수 도메인/키를 사용한다. 한 결과를 새로 뽑는 동작이 다른 속성에 영향을 주지 않는다.

## 3. 로딩과 메모리 사용

활성 메모리는 플레이어 시야와 실제 충돌에 필요한 영역으로 제한한다.

- 렌더링은 플레이어 기준 최대 16m 시야 안의 청크/구역만 표시한다.
- 물리/충돌은 플레이어, 열차, 포탈 통로가 실제 점유하거나 바로 진입할 수 있는 현재·인접 구역만 활성화한다.
- 먼지 안개 밖의 청크는 보이지 않더라도 다음 이동에 필요한 골격만 미리 준비할 수 있다. 모든 블록 메시·광물·아이템을 먼 거리까지 생성하지 않는다.
- 거대한 저장 배열을 계속 붙들지 않고, 현재 활성 청크와 일시 보존 중인 전환 청크만 메모리에 둔다.
- 마지막 차량 통과를 기다리는 포탈 전환 청크는 통과 완료/취소 판정 전까지 예외적으로 유지한다.
- 청크 생성/메시/물리 작업이 지연되면 플레이어와 열차는 경계 앞에서 안전 정지한다. 미생성 공간으로 전진하거나 바닥 없는 영역을 보여주지 않는다.

활성 주변 청크 수, 메시 생성 예산, 모바일 메모리 상한과 선행 생성 거리는 기기 성능 측정 후 설정한다.

## 4. 시야와 먼지 가림

시야는 작업등, 지형 차폐, 먼지 안개 세 가지 결과로 결정한다.

- 작업등은 조준 방향의 가까운 암반과 먼지를 비춘다. 전역 주변광으로 지하를 밝히지 않는다.
- 암반은 시야를 차단한다. 청크가 로드됐다는 이유만으로 벽 뒤 물체나 포탈을 보여주지 않는다.
- 먼지 안개는 시야 상한 16m 안에서 거리에 따라 대비와 선명도를 낮춘다. 먼지가 짙은 지역은 이보다 가까운 거리에서도 가릴 수 있다.
- 센서가 제공하는 중력/포탈 신호는 광학 시야와 별개다. 센서 표시가 벽 뒤 물체의 렌더링이나 청크 전체 지도를 공개하지 않는다.
- 먼지 파티클 수는 화면 표현에만 제한을 둘 수 있지만 실제 포탈 유입/방출 물리 대상과 누적 보상은 별도 이벤트로 관리한다.

먼지 밀도별 감쇠 곡선과 작업등 범위는 화면 검증 전까지 설정값이다.

## 5. 먼 청크 붕괴와 임시 기록 초기화

플레이어가 현재 청크를 완전히 벗어나고 이전 청크가 최대 시야/활성 경계보다 멀어지면 해당 청크는 먼 청크로 판정되어 붕괴할 수 있다. 일반 이동에서는 플레이어 위치와 청크 경계를 기준으로 처리한다. 포탈 전환은 별도 규칙을 적용한다.

- 붕괴 대상의 청크별 암반, 굴착 흔적, 미확인 신호, 바닥 드롭, 포탈 연결, 중력장과 임시 물리 상태를 삭제한다.
- 붕괴된 청크의 좌표·환경 기록은 새 환경 생성에 재사용하지 않는다. 같은 좌표가 나중에 다시 생기면 새 epoch를 부여한다.
- 전체 열차 길이가 16m를 넘으면 후미 차량이 플레이어에게서 멀어진 붕괴 대상 청크에 남을 수 있다. 해당 청크가 붕괴할 때 그 안의 차량과 화물이 소실될 수 있다.
- 열차 길이 16m 이하는 이 초과 길이 소실 규칙에서 안전 범위다. 포탈 통과 도중 출발 청크는 열차 전체가 출구를 벗어나기 전에는 초기화하지 않는다.
- 청크가 아직 열차/포탈 물리 전환 과정에 있어야 하는지 판단하기 어렵거나 차량 위치 저장이 실패하면 붕괴를 보류한다. 단, 일반적인 16m 초과 편성의 후미 소실 위험은 플레이 전에 고지한다.

정확한 먼 거리 경계값은 16m 시야와 함께 시작값으로 설정하고 모바일 시각·물리 검증 후 조정한다. 포탈 특별 보존 상태가 먼 청크 일반 규칙에 우선한다.

## 6. 영구 진행과 환경 상태 분리

| 영구 플레이어 진행 | 청크 임시 환경 |
| --- | --- |
| 장비와 강화, 드릴별 내구도 | 암반과 굴착 이력 |
| 인벤토리·열차 화물·거래 잔액/완료 내역 | 광물 배치 결과와 바닥 드롭 |
| 확인된 발견 조감도·연구·레시피 | 포탈 쌍/현재 위치 및 미세중력 판정 |
| 서사 단서 해금 및 기록 설정 | 청크 안의 먼지·임시 물체·미확인 신호 |

포탈 전환이나 일반 청크 붕괴는 영구 진행을 지우지 않는다. 단, 청크에 남겨둔 바닥 물품과 16m 초과 열차가 먼 청크 붕괴로 잃는 차량/화물은 환경 소실 위험에 포함된다.

청크 초기화 직전에는 아직 정산하지 않은 채굴 보상을 먼저 완료하거나 붕괴를 보류한다. 인벤토리/도감/장비와 임시 청크 데이터를 한 번에 지우지 않는다.

## 7. 세션·재접속·공유 복원

- 활성 세션에서 로드된 청크는 같은 epoch 동안 동일한 포탈/중력/노출 블록 상태를 유지한다.
- 재접속 시 위치와 임시 월드 환경은 새로 생성한다. 영구 플레이어 진행은 별도 저장/복원 규칙에 따라 이어진다.
- 공유 복원 코드는 열차·장비·재료·연구·발견 조감도 같은 공유 가능한 진행을 복원한다. 청크 좌표, 환경 중력장, 숨겨진 포탈 목적지, 아직 노출하지 않은 블록 결과는 포함하지 않는다.
- 복원 적용 전 현재 진행을 클립보드로 백업한다. 백업/저장 충돌 시 현재 진행을 보존하고 청크 붕괴·초기화를 진행하지 않는다.

## 8. 미정 설정과 완료 기준

미정: 먼 청크 붕괴 거리/히스테리시스, 선행 생성 구간, 활성 청크 수/메모리 예산, 먼지 감쇠 곡선, 작업등 범위, 청크 epoch 보존/삭제 구현, 저장 압축 방식.

완료 기준:

- 16m 정육면체/0.5m 복셀/32³ 복셀 수치가 청크 좌표계·렌더·충돌에서 일치한다.
- 청크는 접근 시 생성되고 광물·아이템은 새 블록 최초 노출 때만 판정한다.
- 최대 시야가 16m를 넘지 않으며 암반 차폐와 먼지 안개가 함께 작동한다.
- 플레이어/열차가 필요한 주변만 물리·메시 활성화하고 로드 지연 시 안전 정지한다.
- 먼 청크 붕괴는 임시 환경만 초기화한다. 영구 장비·인벤토리·연구·발견 기록은 분리해 보존한다.
- 총 열차 길이가 16m를 넘으면 후미가 남은 먼 청크 붕괴에서 차량/화물이 소실될 수 있음을 알리고, 포탈 출발 청크는 전체 통과 전까지 유지한다.
- 붕괴·재접속·복원은 저장 충돌이나 미정산 보상을 유실시키지 않는다.
