# DIG 4D 솔로 스토리 암시 대사 구현 상세설계


**구현 상태(2026-11-27, `next/story.js`).** 6개 분류 각 4줄, 사건 키 중복 방지, `dig4-story-v1` 별도 저장, 최소 간격 150초·세션 4회·4초 표시, 인트로·메뉴·엔딩·기억 문장·탭 비활성 시 보류. 사건 연결: 포탈 도착(`arrival`), 거래 화면 3초 관측(`trader_signal`, `quote_observed`), 미지 물질 분석 완료(`material_identified`), 외계 생물 첫 발견(`life_found`), 기억막 판독·몸체 조각(`memory_recognized`). 포탈 너머 장면 프리셋 변경은 시험판에 장면 프리셋이 없어 포탈 도착으로 대신한다.
2026-11-25 · 온라인 모드로 이어지는 숨겨진 세계관을 솔로 플레이에서 간헐적으로 암시하는 대사 시스템

## 1. 목적과 범위

솔로 플레이 중 짧은 대사 단서를 드물게 보여 주어, 플레이어가 만나는 다른 채굴 기계·시간대 간 거래·외계 물질·우주 생물의 정체에 의문을 갖게 한다. 진실은 추후 온라인 모드에서 함께 밝혀질 수 있도록 여지를 남긴다.

첫 인트로는 정해진 암석 수집과 드릴 제작에 집중하므로 세계관 대사를 출력하지 않는다. 본 설계는 4D 솔로 모드의 플레이 중 대사 선택·중복 방지·표시 동작을 정의한다. 온라인 모드의 대화/네트워크 기능, 완성된 스토리 공개, 성우 음성은 범위 밖이다.

## 2. 세계관 사실과 노출 경계

| 내부적으로 참인 설정 | 솔로에서 허용할 단서 | 솔로에서 금지할 직접 설명 |
| --- | --- | --- |
| 포탈은 공간과 시간대를 함께 연결 | 같은 장소가 다른 시점처럼 보이는 장면, 기계 시계와 센서의 불일치 | “포탈은 과거/미래 지구로 연결된다” |
| 거래 상대는 다른 시간대의 채굴 기계 | 상대의 작업 주기·응답이 플레이어와 묘하게 닮음 | “저쪽은 다른 시간대의 지구 채굴 기계다” |
| 외계 물질은 미래 지구에서 개발됨 | 지구 표준 부품과 닮은 규격·제조 흔적·연도 표기 | “이 물질은 미래 지구에서 만들어졌다” |
| 외계 생물은 우주에 적응해 진화한 지구 생물 | 익숙한 생체 패턴, 지구 생물 분류 체계와의 부분 일치 | “이 생물은 우주에서 진화한 지구 생물이다” |
| 플레이어의 개인 기억은 손상됨 | 단서를 알아본 듯한 반응 후 기억하지 못함 | 인공지능의 정체나 과거를 확정하는 고백 |

대사는 세계관 해설이 아니라 관측·오류·자기 의심 형식으로 작성한다. 이미 발견한 정체를 연속 대사로 확인해 주지 않는다.

## 3. 이벤트 계약

게임 시스템은 렌더 프레임마다 대사를 요청하지 않는다. 의미 있는 사건이 완료된 시점에 타입이 지정된 이벤트를 한 번 발행한다.

| 이벤트 | 발생 조건 | 중복 키 예시 | 서사 카테고리 |
| --- | --- | --- | --- |
| `portal_preview_changed` | 포탈 너머 장면이 다른 시점/장소 프리셋으로 바뀌어 플레이어가 실제 시야에서 확인 | 포탈 ID + 장면 프리셋 ID | 시간대 단서 |
| `unknown_miner_signal` | 거래 드론이 새 채굴 기계 신호를 처음 확인 | 상대 기계 프로필 ID | 다른 채굴 기계 |
| `trade_quote_observed` | 매매 화면에서 이전과 다른 변동 가격을 플레이어가 열어 확인 | 물품 ID + 시장 구간 키 | 시간대 거래 |
| `future_material_identified` | 미확인 물질을 처음 분석해 발견 도감에 등록 | 발견물 ID | 미래 지구 물질 |
| `space_adapted_life_identified` | 생물 잔해/표본을 처음 분석해 도감에 등록 | 발견물 ID | 생물 기원 |
| `memory_fragment_recognized` | 현재 단서가 기계의 기억 파편과 유사한 반응을 일으킴 | 기억 파편 ID | 기억 손상 |

UI를 열어 둔 것만으로 이벤트를 확정하지 않는다. 가격 관측은 해당 가격표가 실제 표시되고 일정 시간 읽을 수 있었을 때만 인정한다. 자동 반복되는 센서 변화·동일 포탈 애니메이션은 새 단서로 세지 않는다.

## 4. 데이터 구조

대사는 코드 내 정적 콘텐츠로 관리하고, 트리거/선택/표시는 분리한다.

```ts
export type StoryClueCategory =
  | 'time_shift' | 'other_miner' | 'trade_echo'
  | 'future_material' | 'adapted_life' | 'memory';

export type StoryClueEvent = Readonly<{
  type: string;
  dedupeKey: string;
  occurredAtMs: number;
  context?: Readonly<Record<string, string | number>>;
}>;

export type StoryLine = Readonly<{
  id: string;
  category: StoryClueCategory;
  text: string;
  triggerTypes: readonly string[];
  prerequisiteIds?: readonly string[];
  weight?: number;
}>;
```

- 콘텐츠에는 표시 문장, 카테고리, 이벤트 조건만 저장한다. 대사 시스템은 인벤토리·크레딧·청크 생성 결과를 수정하지 않는다.
- 동일 `dedupeKey`는 한 솔로 진행에서 다시 발화하지 않는다. 진행별 대사 플래그는 게임 세이브 본문과 분리된 `dig4-story-v1` 저장공간에 둔다. 새 게임 초기화에서는 이 저장공간도 플레이어가 선택적으로 초기화하도록 연결한다.
- 월드 위치·청크 좌표·시간대 목적지 정보는 이 저장공간에 기록하지 않는다. 이벤트에는 필요한 최소 식별자만 전달한다.
- 저장이 불가능하거나 쓰기에 실패하면 현재 세션 메모리에서 중복만 억제하고 게임 진행을 막지 않는다.

## 5. 선택 및 빈도 제한

1. 이벤트가 발생하면 카테고리·중복 키를 확인한다. 이미 소비된 키면 종료한다.
2. 인트로, 복원, 일시정지, 메뉴/거래 패널 열림, 탭 비활성 상태에서는 큐에 보류한다. 오래된 단서는 현재 플레이와 무관해지면 버린다.
3. 같은 사건의 중복 이벤트를 합치고, 표시 가능한 한 개만 대기 큐에 둔다. 큐가 찼을 때는 새 대사로 덮어쓰지 않는다.
4. 대사 선택 시 해당 카테고리에서 아직 보지 않은 문장만 후보로 삼고, 선행 단서가 있으면 순서를 지킨다. 의미가 중복되는 문장은 연속으로 고르지 않는다.
5. 대사 하나가 4초 표시된 뒤 서서히 사라진다. 기본 재생 간격은 4분, 전역 최소 간격은 150초, 한 세션 최대 4회로 시작한다. 모든 값은 콘텐츠 설정으로 조정 가능하며 확정 밸런스가 아니라 초기 구현값이다.
6. 대사 출력 중 채굴·이동·포탈 물리는 멈추지 않는다. 텍스트는 화면 중앙 조준점과 버튼을 피하는 하단 안전 영역에 표시하고, 탭 입력을 가로채지 않는다.
7. 앱을 떠났다가 돌아오면 대사 노출 시간을 이어서 계산하지 않는다. 예약 시간이 지났더라도 즉시 팝업하지 말고 다음 안전한 순간까지 대기한다.

새 게임 세이브에도 세계관 단서는 조건을 만족할 때 등장할 수 있다. 다만 시작 연출에는 나타나지 않는다. 재접속 전용 기억 독백은 별도 선택기와 표시 규칙을 유지하고, 두 대사를 같은 프레임에 겹치지 않는다.

## 6. 초기 대사 풀 방향

초기 버전은 카테고리마다 3~5개의 짧은 문장을 제공한다. 다음은 톤 가이드이며 콘텐츠 확정 원문은 아니다.

| 카테고리 | 톤 예시 |
| --- | --- |
| 시간대 단서 | “센서 기록 시각이 관측한 장면보다 앞서 있어.” |
| 다른 채굴 기계 | “저쪽 작업 리듬… 내 장비 진동과 너무 비슷해.” |
| 거래의 흔적 | “이 부품 규격을 알고 있었던 것 같은데.” |
| 미래 물질 | “분석표에 없는 제조 표식. 그런데 읽을 수는 있어.” |
| 생물 기원 | “낯선 조직인데, 분류표가 익숙한 이름을 찾고 있어.” |
| 기억 파편 | “왜 이 소리를 기다렸던 것 같지?” |

톤은 기억 손상과 어울리는 관측 보고/자기 의심 형식으로 유지한다. 직접 정답을 말하는 문장이나 긴 서사 독백은 넣지 않는다.

## 7. 코드 구성과 연결점

- `storyClueContent.ts`: 타입 안전한 대사 콘텐츠와 prerequisite 목록.
- `storyClueTriggers.ts`: 도감 등록, 포탈 미리보기 변경, 드론 신호/가격 표시 등 시스템 이벤트를 서사 이벤트로 변환한다. 게임 시스템은 대사 UI를 직접 호출하지 않는다.
- `storyClueDirector.ts`: 중복 방지, 저장 플래그, 선행 조건, 카테고리 선택, 빈도 제한, 큐 관리.
- `storyCluePresentation.ts`: 텍스트 표시 시간·페이드·접근성 알림을 담당한다.
- `main.ts`: 솔로 4D 런타임 초기화 때 director를 한 번 생성하고, 시스템에서 발행된 이벤트를 전달한다. 기존 `reconnectMemoryDialogue.ts`는 재접속 전용으로 유지한다.
- `dig-4d.html`: 재사용 가능한 `#story-line` 시각 영역을 추가한다. 이미 있는 `#reconnect-line`과 겹치면 단서 대사를 미루고, 숨김 상태 및 `aria-live="polite"`를 적용한다.
- 이후 온라인 구현에서는 콘텐츠 ID와 이벤트 계약을 재사용할 수 있지만, 플레이어별 노출/진행 저장 정책은 서버 세션 설계 단계에서 별도로 결정한다.

## 8. 초기 검증 시나리오와 완료 기준

- 인트로 중 조건에 맞는 이벤트가 실수로 발행되어도 대사가 표시되지 않는다.
- 첫 물질 식별은 단서를 만들고, 동일 물질 재확인·메시 재생성은 중복 대사를 만들지 않는다.
- 같은 포탈 장면이 주기적으로 반복 전환되어도 한 번만 단서를 준다. 새로운 프리셋/포탈만 새 단서 후보가 된다.
- 거래창 가격을 반복 열어도 가격 변경 단서가 과도하게 쌓이지 않고, 중복·전역 재생 간격을 지킨다.
- 범주/선행 조건을 충족한 문장만 선택되며, 난수 경계값에서도 후보가 없거나 잘못된 인덱스가 반환되지 않는다.
- 메뉴/복원/탭 비활성화 도중 텍스트가 표시되지 않고, 재개 뒤에도 입력 및 자동 채굴이 방해받지 않는다.
- 재접속 독백과 세계관 단서가 동시에 표시되지 않는다. 세이브 데이터·인벤토리·경제 상태는 대사 시스템 도입 전후 동일하다.
- 스토리 단서 저장 실패는 게임 플레이를 막지 않고 세션 내 중복만 방지한다.

## 9. 구현 순서

1. 기존 대사·HUD 연결을 확인하고 정적 데이터 타입과 콘텐츠 카테고리를 추가한다.
2. 순수 이벤트 중복 방지기와 선택기를 만든다.
3. 별도 진행 저장공간과 읽기/쓰기 실패 fallback을 연결한다.
4. 이벤트 생산자(발견물, 포탈 장면, 드론 신호/가격)를 하나씩 연결한다. 시스템별 기능이 없으면 이벤트는 구현하지 않고 대기한다.
5. 하단 표시 UI와 재접속 대사 충돌 방지를 연결한다.
6. 중복·빈도·세이브 비변경·접근성 시나리오를 자동 검증한다.
7. 실제 공개 4D 페이지에서 모바일 터치, 자동 전진 중 표시, 저조도 가독성을 확인한다.

### 구현 차단 선행조건

현재 4D에는 실제 포탈 페어, 도감 물품, 거래 드론/변동 시세가 연결되지 않았다. 대사 director와 테스트는 선행 구현 가능하지만 해당 콘텐츠 이벤트의 실제 플레이 연결은 각 생산 시스템이 들어온 뒤에 진행한다. 이전 소형 포탈 확률 프로토타입과 최신 시작 청크 입구 보장 규칙을 함께 구현할 때 생성 정책을 먼저 합쳐야 한다.
